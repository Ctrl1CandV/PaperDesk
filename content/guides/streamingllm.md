# StreamingLLM：有限缓存怎样支撑持续输入

一段文本持续到来时，语言模型不一定需要同时保留其中每个词，但它需要在丢弃旧信息后继续正常工作。这两个要求看起来接近，实际却不同：限制缓存解决的是资源消耗，淘汰缓存后仍能可靠预测才是模型行为问题。StreamingLLM 的价值，就在于找出了一个容易被忽略的失败原因，并用很小的缓存调整让已有模型持续处理长文本。

Guangxuan Xiao、Yuandong Tian、Beidi Chen、Song Han 和 Mike Lewis 的论文发表于 ICLR 2024。本导读的技术依据固定为 2024 年 4 月 7 日的 arXiv v4，会议页面只用于核验发表信息。阅读重点是“输入流可以很长，但当下可用的上下文仍然有限”这一边界；本文没有证明模型能记住无限历史，也没有研究生成答案途中怎样异步接收新观察并修订推理。[论文 v4，§1–2、附录 A](https://arxiv.org/html/2309.17453v4)；[ICLR 2024 正式发表记录](https://proceedings.iclr.cc/paper_files/paper/2024/hash/5e5fd18f863cbe6d8ae392a93fd271c9-Abstract-Conference.html)

## 先把持续运行、上下文窗口和记忆分开

自回归语言模型根据已有 token 预测下一个 token。解码时，Transformer 通常缓存以前 token 在各层产生的 Key 和 Value，也就是 KV cache。新的 Query 可以与缓存中的 Key 计算注意力，再用得到的权重汇聚 Value，避免每一步重新计算整段历史的表示。这里的缓存是一次推理过程中的中间状态，并不等于把知识写入模型参数，也不等于一个可以按语义检索的外部记忆库。

如果不断保留所有 KV，输入越长，缓存越大，当前 token 需要关注的对象也越多。同时，模型是在有限长度的文本上训练的，把位置和距离推到远超训练范围，不保证还保持原来的行为。作者因此把问题收窄为：能否使用有界缓存，让已有模型持续基于近期上下文生成，而不因运行时间增长而崩溃？这不同于把一次可关注的上下文窗口扩大，也不同于提升模型利用长文中每个细节的能力。[论文 v4，§1–2](https://arxiv.org/html/2309.17453v4)

可以用一个教学例子理解这一区别。连续读入很多设备日志时，“现在仍能解释最近几条日志”是持续运行；“现在能同时比较很长一段日志”要求更大的有效上下文；“现在能找回很久以前某次故障”还需要保留与找回旧证据。StreamingLLM 主要处理第一个问题。这个例子是导读的概念说明，不是论文验证过的工业应用。

## 为什么只留下最近一段文本还不够

最直接的办法是滑动窗口：缓存达到容量后，每来一个新 token，就淘汰最老的 KV。它使缓存大小稳定，却在作者测试的模型中出现异常：开头 token 被移出后，语言建模困惑度突然上升。困惑度可以理解为模型对真实后续文本预测的不确定程度；在同一评价设置下，较低通常表示更好的预测。突增意味着模型连近期文本的概率分布也不能正常建模，不能只用“它忘记了远处事实”来解释。[论文 v4，§3.1、图3](https://arxiv.org/html/2309.17453v4)

论文另设了一个更昂贵的基线：每预测下一个 token，都拿最近一段原始文本重新计算整段 KV。它能够维持较好的困惑度，却重复处理窗口中的大量内容。普通窗口缓存和每步重算因此不能混为一谈：前者保留并复用中间状态，后者每次重新建立当前窗口的计算过程。论文图1用这一区别比较效率与质量，而不只是比较“保留多少文本”。[论文 v4，§1、图1](https://arxiv.org/html/2309.17453v4)

研究推进的关键，是把异常定位到“最初的 KV 离开缓存”的时刻。这使一个宽泛的长文本问题变成了可检验的问题：开头重要，究竟因为那里包含了重要语义，还是因为模型学会了依赖这个位置？

## Attention sink 是注意力分配现象，不是历史摘要

在作者可视化的 Llama-2-7B 中，底部两层更偏向近期 token，较深层则对开头位置分配了很强的注意力。作者将这类接收大量注意力的 token 称为 attention sink，可以译作“注意力汇聚点”。这里的注意力强弱不能直接解释成事实的重要程度，更不能解释成“最初几个 token 储存了后来所有历史”。[论文 v4，§3.1、图2](https://arxiv.org/html/2309.17453v4)

理解其作用，只需要看 softmax 归一化。用 $x_i$ 表示某个 Key 对当前 Query 的注意力分数，其权重为：

$$
\alpha_i=\frac{e^{x_i}}{\sum_{j=1}^{N}e^{x_j}}.
$$

这些权重总和为 1。如果开头位置长期占据很大权重，把它移除就不仅少了一条信息，还改变了其他位置的归一化分母，重新分配了整组注意力。作者的解释是：某些注意力头即使没有需要提取的内容，也必须分配总量为 1 的注意力；开头 token 对后续位置普遍可见，容易在训练中成为接收这些注意力的对象。这是论文用实验支持的机制解释，不是仅由 softmax 公式就能证明“所有模型必然选择最初四个 token”的定理。[论文 v4，§3.1、公式1](https://arxiv.org/html/2309.17453v4)

为了区分语义和位置，作者把最初四个 token 换成换行符。Llama-2-13B 在 PG19 测试集第一本约 65K token 的书上，使用总计 1024 个 KV 时，纯近期窗口的困惑度为 5158.07；保留最初 4 个与最近 1020 个后为 5.40；换成四个起始换行符后为 5.60。替换开头语义仍能恢复表现，支持了“汇聚点功能不依赖原开头内容”的解释。这项干预不能推广成任意替换、任意模型都成立。[论文 v4，表1](https://arxiv.org/html/2309.17453v4)

## 两段缓存还需要配套的位置处理

StreamingLLM 把缓存分成两个部分：固定保留少数最初 token 的 KV，同时滚动保留最近 token 的 KV；中间已经过期的部分逐步移出。论文记号 $x+y$ 表示 $x$ 个初始 token 加 $y$ 个近期 token。例如 $4+1020$ 的总缓存为 1024，而不是在 1024 之外再加 4。前一部分稳定注意力分配，后一部分主要提供当前语言建模所需的近期内容。[论文 v4，§3.2、图4](https://arxiv.org/html/2309.17453v4)

但只保留两段 KV 还不完整。假设原始 token 编号为 0 到 9，当前保留的是 0、1、2、3、6、7、8，正准备处理 9。论文让本次注意力使用连续的缓存位置 0、1、2、3、4、5、6、7，而不是沿用带有中间缺口的原始编号。这样，汇聚点与近期内容的相对距离不会随着整个输入流无限增大。[论文 v4，§3.2](https://arxiv.org/html/2309.17453v4)

位置处理取决于模型。对于 RoPE，论文缓存加入旋转位置变换之前的 Key，每个解码阶段按缓存中的位置施加变换；对于 ALiBi，则用连续的距离偏置计算注意力，避免跨过已淘汰段的距离跳变。重排的是注意力计算所使用的位置，不是把那些被淘汰的文本重新找回来。这里的兼容性讨论针对论文涉及的相对位置编码机制，不能把方法当作对任意模型都只需改一个列表的通用插件。

保留四个初始 token 是作者据消融选择的默认值。表2显示模型差异明显：某些被测模型保留一个便已接近恢复，而 Llama-2-7B 在相同总容量下保留四个优于一两个；继续增加到八个的收益很小。因此，“四个通常够用”是这些实验中的经验结论，应与模型、缓存容量和任务一起理解。[论文 v4，§3.2、§4.4、表2](https://arxiv.org/html/2309.17453v4)

## 四百万 token 和速度收益各自在测什么

语言建模实验将 PG19 测试集的 100 本书拼接成长序列。§4.1 中 Llama-2 的缓存容量为 2048，Falcon、Pythia 和 MPT 为 1024，均默认保留四个初始 token。图3先比较约 20K token 内的困惑度变化；图5再把连续评价推进到超过四百万 token，展示多种模型规模下的稳定趋势。书与书的交接会造成波动，稳定不意味着曲线恒定。[论文 v4，§4.1、图3、图5](https://arxiv.org/html/2309.17453v4)

这说明固定缓存可以持续对很长的已给定文本做后续 token 预测，没有出现单纯滑窗那样的崩溃。它不等于自由生成四百万 token 都保持事实一致，也不等于任意时刻都能检索第一本书中的细节。理解这组实验时，要把“已经处理过的累计长度”和“本次预测可直接关注的缓存内容”分开。

效率实验则比较 StreamingLLM 与每步重算滑动窗口。两者使用 Hugging Face Transformers，在单张 NVIDIA A6000 上测试 Llama-2-7B 和 13B；图10横轴是缓存容量，比较每 token 解码延迟和显存。论文报告最高 22.2 倍的每 token 加速：图中 Llama-2-13B、缓存 4096 时，延迟标值约为 2355 毫秒与 106 毫秒；显存用量接近重算基线。这是指定实现、模型、硬件和缓存设置中的最大相对收益，不是相对所有推理系统的固定加速比。[论文 v4，§4.5、图10](https://arxiv.org/html/2309.17453v4)

图1给出的注意力计算量有助于解释趋势。用 $T$ 表示累计 token 数、$L$ 表示有限窗口大小，完整注意力的累计计算量约为 $O(T^2)$；滚动使用窗口约为 $O(TL)$；每步重算窗口则约为 $O(TL^2)$。这些是论文用于比较注意力部分的量级，未把模型前馈层、数据搬运等所有成本写入同一个公式，也不意味着固定缓存后完整系统的实际延迟完全不变。[论文 v4，图1、§4.5](https://arxiv.org/html/2309.17453v4)

## 问答实验说明了有效近期上下文的边界

论文用两种问答设置补充困惑度。第一种把 ARC 问答连续输入，在每个答案位置检查模型输出。总缓存为 1024 时，StreamingLLM 的结果接近逐题单独处理的基线，而普通窗口明显下降。这说明已有指令模型可以在连续流程中维持答题能力，但每题主要依赖当前题目，不能据此证明它保存了所有先前问题。[论文 v4，§4.3、表5](https://arxiv.org/html/2309.17453v4)

第二种是合成数据集 StreamEval：不断输入信息行，每增加 10 行提出一个问题，答案位于此前 20 行。图8展示样例，图9比较累计输入长度增加时的准确率，结果对 100 个样本取平均。因为所问信息始终较近，这项测试把“长期持续处理”与“近期信息访问”结合了起来；它有意区别于在长文末尾只提一次跨越整段历史的问题。[论文 v4，§4.3、图8–9](https://arxiv.org/html/2309.17453v4)

附录 C 进一步增大问题与答案的距离。对 Llama-2-7B-32K-Instruct，采用 $4+2044$ 缓存时，距离 20 行即 460 token 的准确率为 85.80%；距离 100 行即 2300 token 时为 0。该表按 100 个样本、每个样本 100 个问题计算。结果既表明超出缓存会丢失所需证据，也显示更大的缓存并不自动带来更高准确率。能放进去、能找到并正确使用，仍是不同要求。[论文 v4，附录 C、表7](https://arxiv.org/html/2309.17453v4)

## 专门训练一个 sink token 是另一组实验

前面的主要方法作用于已有模型，不要求微调。论文还提出一个训练阶段的改动：在每个训练样本开头加入可学习的专用 sink token，让它承担汇聚点功能，减少对多个普通初始 token 的依赖。作者也比较了 Zero Sink，即把 softmax 分母改为 $1+\sum_j e^{x_j}$；它可以视为额外加入 Key、Value 为零的注意力位置，使分配给实际内容 token 的权重不必总和为 1。[论文 v4，§3.3、公式2、表3](https://arxiv.org/html/2309.17453v4)

这些预训练验证使用 160M 参数模型。§4.2 的普通模型与专用 sink token 模型沿用 Pythia-160M 的训练方案，使用去重的 Pile、批大小 256，训练 143000 步。论文报告二者收敛趋势及七个 NLP 基准表现相近；专用 token 模型在流式运行时只保留这个 token 就能取得较稳定的困惑度，而 Zero Sink 未完全消除对其他初始 token 的依赖。[论文 v4，§3.3、§4.2、表3–4、图6–7](https://arxiv.org/html/2309.17453v4)

这组证据加强了“给注意力分配预留位置有用”的解释，但规模和训练设置有明确范围。不能据此说任意大模型都已经验证了同样收益，也不能把“训练过专用 token”简化为在已有聊天提示词前临时加一个特殊词。

## 怎样把它接到持续理解这一学习方向

StreamingLLM 给出了一个清晰的底层认识：让模型一直处理输入，需要维护合适的计算状态；丢弃旧状态可能改变当前计算，不能只按文本新旧决定是否删除。同时，论文也主动保留了边界：它没有扩大上下文窗口，没有增强长期记忆；需要大量远处证据的长文问答和总结并非它的主要适用任务。[论文 v4，附录 A、C–D](https://arxiv.org/html/2309.17453v4)

附录 D 的 LongBench 对照还提醒了另一点：保留汇聚点不保证保留任务指令或正文证据。Llama-2-7B-Chat 使用 $4+3496$ 时，多个长文任务弱于保留头尾各 1750 token 的截断基线；将 StreamingLLM 也设为 $1750+1750$ 后，结果接近截断基线。作者将前一种下降归因于可能丢失了关键开头信息。这说明“稳定计算所需的位置”与“任务语义所需的内容”可以提出不同的保留要求。[论文 v4，附录 D、表8](https://arxiv.org/html/2309.17453v4)

由此可以形成后续阅读的分工。缓存管理解释当前计算怎样持续进行；记忆机制解释什么旧信息应保存、如何找回；在线决策和推理修订则关心新观察何时改变判断与行动。这是本导读提出的学习衔接，不是作者已经实现的三层系统。若问题是“模型正在思考时，新证据来了怎么办”，本文只能提供持续 token 处理的一块基础，不能回答中断、并发观察或撤销旧决策的策略。

阅读后可以自检三个问题：为什么四百万累计输入不等于四百万上下文？为什么高注意力的初始 token 不等于高语义价值的历史记忆？为什么比较速度前必须先确认基线是缓存复用还是每步重算？能用缓存内容、位置处理和实验设置解释这三个区别，比记住“保留四个 token”更接近本文的研究贡献。
