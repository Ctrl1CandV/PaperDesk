# AgentPrune：哪些智能体消息可以不再发送

多智能体系统常把上一轮的回答广播给其他成员，希望大家相互补充。但发送更多消息既消耗上下文，也可能传播重复或错误的信息。AgentPrune 把通信关系表示成图，再学习删掉其中一部分连接，研究怎样在保留任务效果的同时降低通信成本。

本文固定于 [arXiv v1](https://arxiv.org/abs/2410.02506v1)（2024-10-03）。重点是图模型、裁剪过程和实验的解释边界，数值不与后续会议版本混用。

## 把同一轮与跨轮消息分开

论文把每个 Agent 表示为带有底座模型、角色、状态和外部工具的节点。边表示消息传递，分成两类：空间边连接同一轮中的参与者，时间边把上一轮输出送到下一轮。这里的“空间”和“时间”是交流组织方式，不是物理网络位置。[图建模 §2](https://arxiv.org/html/2410.02506v1#S2)

例如，在教学情境中，甲先提出方案，乙本轮检查它，这是空间边；如果乙的检查意见在下一轮又交给甲，就是时间边。删掉前者可能使检查者失去对象，删掉后者可能让修改者忘记错误。两类边都消耗 token，却承担不同责任，因此值得分别分析。

论文按拓扑顺序执行同一轮的计算，要求使用的空间图是有向无环图。这是其建模与执行选择，并不意味着所有多智能体系统天然都是 DAG。要把异步交谈或循环调用系统映射过来，需要先解释什么算一轮以及依赖怎样展开。

## 为什么通信冗余需要实验证据

作者在四个 GPT-3.5-turbo Agent 的 MMLU 实验中，对密集通信与辩论结构随机删除部分连接，发现适度删除有时不会降低、甚至会提高成绩。这说明在这些条件下，消息数量与效果并非单调关系；删除过多仍可能破坏协作。[§2 与图 3](https://arxiv.org/html/2410.02506v1#S2)

“冗余”在这里是相对于任务效用而言的：若少一些边仍能达到相近效果，就有减少交流的空间。它并不是说某段语言在语义上重复，就一定能够删除。包含相同事实的两条消息，可能分别给不同参与者提供必要信息。

反过来，图中存在一个效果相近的子图，也不代表算法总能找到它，或对新任务仍然有效。定义目标、找到结构和验证泛化，是三个不同环节。

## 先学习连接的重要程度，再固定稀疏图

AgentPrune 从原有空间和时间邻接矩阵出发，分别乘上可学习的图掩码。原图决定哪些连接可以使用，掩码帮助选择其中的重要连接；这不是给语言模型参数做剪枝，也不是重新训练底座模型。[方法 §3.1–3.3](https://arxiv.org/html/2410.02506v1#S3)

由于任务得分可能来自外部评价或代码运行，通常不能直接对得分求普通反向传播梯度，论文使用策略梯度更新连接选择：按掩码采样通信结构，用任务得分反馈调整连接权重。方法还加入低秩约束，以核范数作为可优化替代；核范数是矩阵奇异值之和。低秩约束表达结构偏好，它不等同于直接统计边数，也不能单独保证每个错误消息都被识别。

经过较短的优化阶段，方法按掩码大小一次性保留指定比例的原有边，形成二值掩码。在之后的对话中使用固定的稀疏结构。理解这一点很重要：论文主流程不是每次收到消息都让另一个模型逐句判断是否转发。

```mermaid

  A[已有空间图与时间图] --> B[短阶段学习连接掩码]
  B --> C[按保留比例一次裁剪]
  C --> D[固定稀疏通信图]
  D --> E[继续任务并评价效果与成本]
```

此图为根据 §3 绘制的教学流程。对于大量较短任务，论文还提出用少量查询学习结构，再用于更多查询，避免每道题重复支付完整优化成本。[适用条件与多查询设置](https://arxiv.org/html/2410.02506v1#S3.SS4)

## 节省成本必须算上学习阶段

删除连接通常减少后续输入，但寻找连接本身要运行模型。若任务很少，或优化阶段消耗很大，总成本不一定下降。论文 §3.4 也限定了适用对象：多于三个 Agent、具有一定复杂度的通信结构；简单链条或直接输出结构并不适合原样套用。

评价时至少应保留任务效果、输入 token、输出 token、结构学习开销和重复使用次数。只报告“删除了一半边”没有说明实际节省：不同边承载的消息长度可能不同，输出也可能随输入变化。若比较费用，还要固定模型与价格口径，不能把历史美元成本当作当前报价。

以上是由方法流程导出的核查方式。本文不使用 v1 的成本推导公式 13 作为已验证的成本保证，也没有运行新的成本实验。

## 实验中的性能与代价怎样一起读

论文用 MMLU、四个数学推理数据集及 HumanEval 检查方法。主表的多 Agent 比较使用五个 GPT-4 Agent；设置描述给出 gpt-4-1106-preview、温度 1，以及一般/数学任务两轮、代码任务四轮等条件。它与前面四个 GPT-3.5 Agent 的随机删边动机实验并非同一配置。[实验设置与表 1](https://arxiv.org/html/2410.02506v1#S4)

图 5 同时展示任务得分和 prompt token 消耗，帮助读者看见某些结构的额外成本。表 3 则把 AgentPrune 接入 AutoGen 与 GPTSwarm。以该表的 AutoGen/HumanEval 条件为例，prompt token 从 492,273 降到 315,105，但 completion token 从 130,196 增到 139,714。这说明输入减少不意味着输出也同步减少。[接入实验与表 3](https://arxiv.org/html/2410.02506v1#S4.SS3)

这张 v1 表的部分 GSM8K 行中，所列比例与原始 token 数值存在不一致，因此本文不沿用这些行的百分比来计算统一节省率。表 1 的部分汇总项也需要回到单项核对。保留方法的研究价值，与审慎对待具体汇总数值并不矛盾。

论文还测试角色提示攻击与替换 Agent 的攻击，观察到部分配置在裁剪后更稳健。[攻击实验 §4.4](https://arxiv.org/html/2410.02506v1#S4.SS4) 这些结果支持在指定威胁模型下进一步研究信息传播，不能扩展为通用防提示注入机制或安全保证。

## 从删边走向可解释的通信选择

对后续研究，一个有价值的问题是：保留下来的边到底传递了什么？同样的裁剪比例，可能保留了关键工具结果，也可能只是保留了某类任务上的统计相关性。可以进一步比较保留错误反馈、角色指令和候选答案的效果，检查任务变化后是否仍有帮助。

另一个问题是固定结构的适用范围。训练时需要规划者先交流的任务，未必适合另一类需要独立检查后汇总的任务。若研究动态选择，应该与固定图在相同总预算下比较，并计入选择器自己的开销。以上是本导读提出的候选方向，不是原文已经完成的实验。
