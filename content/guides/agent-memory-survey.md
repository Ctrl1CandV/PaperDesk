# Agent 记忆综述：过去的信息怎样参与下一次判断

当一个 Agent 能检索资料、调用工具并连续完成多个步骤之后，一个基础问题会逐渐显现：过去发生的事情，怎样继续影响现在？保存聊天记录只是可能的办法之一。系统还可能保存执行轨迹、失败后的解释、可复用技能，或者把知识写进模型参数。这些都叫“记忆”，但它们保留的信息、更新方式和能支持的行为并不相同。

Zeyu Zhang 等人的这篇综述用“是什么、为什么需要、怎样实现、怎样评价”串起这一领域。本导读固定依据 2024 年 4 月 21 日的 arXiv v1，重点解释其中的分类关系和判断方法。它可以承接 RAG、ReAct、Reflexion，帮助把分散的方法放到同一张概念地图上；它不是实时感知、信念修订或动态决策理论的总综述。[论文 v1，§1、§3–6](https://arxiv.org/html/2404.13501v1)

## 先界定记忆跨越了什么边界

论文先区分 task、trial 和 step。task 是要完成的任务；trial 是一次完整的求解尝试；step 是尝试中的一次交互。同一个任务可以经历多次尝试，每次尝试又包含多个行动及环境反馈。区分这三层，才能说清“以前的信息”究竟来自哪里。

作者的狭义记忆只涉及当前尝试已经发生的历史。比如在一个纯教学情境中，Agent 正在检查设备，前一步已经确认电源正常，这条观察应当影响后续排查。广义记忆进一步包含先前尝试、其他任务的经验，以及交互过程之外的知识。先前某次排查失败的原因，与设备手册中的工作原理，都可能帮助当前行动，但它们具有不同来源。[论文 v1，§3.1–3.3；手动定位这些小节](https://arxiv.org/html/2404.13501v1)

这个定义比“长期保存的个人信息”宽得多。当前上下文也可以承担记忆功能，资料库也可以是记忆来源。反过来，存在一个永久数据库，并不能说明 Agent 已经会利用历史：内容可能没有被选中，也可能被错误解释。

还要注意 trial 的划分依赖任务设计。持续对话可以被视作一个很长的尝试，也可以按会话拆开。因此，不能仅根据“跨不跨 trial”就推断真实时间长度，更不能把跨尝试记忆直接等同于模型参数更新。阅读后续论文时，应先确认作者把哪些交互划在同一次尝试之内。

## 为什么需要记忆：从保存经历到利用经历

作者从认知心理学、自我演化和应用需求三个角度说明记忆的必要性。认知心理学部分借用人类积累经历、形成概念与利用过去指导行为的思路；这是设计启发，并不是“Agent 的记忆与人脑具有相同机制”的实验证明。

自我演化在这里主要涉及三件事：保留成功或失败的经验，利用历史决定下一步探索，以及从具体观察抽取可迁移的知识。假如每次失败以后只重新开始而不保留任何反馈，下次求解就缺少利用这次经历的渠道。但“存过失败记录”和“已经学会避免失败”之间仍有距离：记录要被找到，解释要正确，适用条件也要与新任务相符。[论文 v1，§4.1–4.3](https://arxiv.org/html/2404.13501v1)

应用需求则给出更直接的理由。多轮对话需要知道先前讨论了什么；角色模拟需要维持角色背景；探索任务需要知道哪些动作试过、带来了什么结果。记忆的价值由这些具体需求体现。作者强调记忆的重要性，不意味着只要增加记忆，系统就会持续进步，也不意味着所有任务都需要同样复杂的长期机制。

## 来源、形式和操作是三个交叉的维度

论文 §5 的分类值得作为阅读坐标，而不是背成一串模块名称：来源回答“信息从哪里来”，形式回答“以什么方式保留”，操作回答“怎样让它进入、变化和发挥作用”。同一条信息可以同时在这三个维度上得到描述。

| 维度 | v1 的主要分类 | 阅读时要辨别的关系 |
|---|---|---|
| 来源 | 当前尝试、跨尝试、外部知识 | 自己经历过的反馈与借来的知识，证据性质不同 |
| 形式 | 文本形式、参数形式 | 信息显式提供给模型，或通过参数影响行为 |
| 操作 | 写入、管理、读取 | 内容能否保存、如何改变、能否在需要时被利用 |

例如，把一次失败概括成“这种输入下应先检查边界条件”，供下一次尝试调用：来源是跨尝试经验，形式是文本，写入与管理把执行反馈变成经验，读取再把经验带入当前任务。若用这些经历微调模型，来源仍然是跨尝试经验，但形式和更新代价已经改变。这个例子是对分类的教学运用，不是原文新增的实验。[论文 v1，§5、§5.1–5.3](https://arxiv.org/html/2404.13501v1)

三种来源各有作用。当前尝试的历史通常最贴近眼前任务，却不一定能提供以往经验；跨尝试内容可以支持错误规避和迁移，却可能来自不适用的新旧情境；外部知识让 Agent 使用无需亲自探索得到的事实，却仍需要检查来源和时效。v1 把外部知识称为交互循环外的信息，同时也讨论通过工具动态获取它。因此，“外部”描述来源，不能理解成现实中的内容永不更新。

这也解释了与已有文章的关系。RAG 有助于理解外部知识的检索与使用；ReAct 展示推理、行动和观察如何连成过程；Reflexion 则突出把尝试后的反馈变成可供下一次使用的文本经验。这里给出的是编辑性的概念衔接，不能据此断言三者使用了同一种记忆算法。

## 文本记忆与参数记忆把成本放在不同地方

文本记忆将内容显式提供给模型。论文在这一类中讨论完整交互、近期交互、检索到的交互和外部知识。它们不必互斥：一个系统可以保留近期上下文，同时检索更早的片段。

完整历史减少了预先筛选造成的丢失，却会增加输入长度和计算负担；内容在上下文中的位置还可能影响利用效果。只保留近期内容，可以控制输入规模，但早期关键条件可能被移出窗口。按相关性检索有机会找回遥远信息，却把问题转移到了检索：当前查询是否表达了真正需求，候选是否遗漏必要证据，以及检索本身是否足够快。[论文 v1，§5.2.1](https://arxiv.org/html/2404.13501v1)

这里的“文本形式”也不意味着实现中没有向量。把一段文本编码成向量用于索引，检索后仍把文本送给模型，在这份综述的语境中仍属于文本记忆。检索索引的表示，与知识是否写进模型参数，是不同层面的问题。

参数记忆通过调整模型参数，使知识或经历影响后续输出。作者主要讨论微调和知识编辑：前者利用数据更新模型，后者围绕特定事实进行有针对性的修改。它们不需要每次把同一段记忆重新放进提示，但写入可能涉及训练、数据准备和额外计算，也可能影响已有知识。[论文 v1，§5.2.2–5.2.3](https://arxiv.org/html/2404.13501v1)

因此，作者所概括的“文本写入较方便、参数读取较方便”应理解成成本分布的比较，不是所有系统中都成立的速度定律。参数记忆没有逐条占用提示长度，也不意味着容量无限或没有信息损失。知识编辑希望保留无关知识，但原文也承认这种保留仍然是挑战，不能把目标当成已经实现的保证。

## 写入、管理和读取共同决定记忆是否有用

写入把新观察变成实际保存的内容。保存原始记录便于回看细节，却可能保留大量重复与噪声；保存摘要更简洁，却提前决定了哪些细节值得留下。这不是单纯的存储格式选择：如果摘要遗漏了一个条件，之后再精巧的检索也无法从这份摘要中恢复那个条件。

管理对已有内容继续加工。综述归纳了合并、反思和遗忘：合并减少重复，反思从具体经历抽取较高层次的信息，遗忘减少无关内容的影响。它们会改变记忆的意义，而不只是改变长度。例如，把“这次失败可能与条件 A 有关”压缩成“A 会导致失败”，已经把暂时解释强化成一般规则。这个例子是导读对证据风险的分析，不是论文报告的实验结果。

读取选择当下需要的信息。论文讨论了相似度检索、结合时间与重要性的信息选择，以及使用 SQL 等方式查询结构化内容。对于参数记忆，利用更新后的模型推理，则可以被视为隐式读取。写入和读取必须配合：如果写入只保留事件结果，后续需要解释失败原因时，就可能缺少必要的过程证据。[论文 v1，§3.4、§5.3.1–5.3.3](https://arxiv.org/html/2404.13501v1)

沿着这三个操作，可以把“记不住”拆成更具体的情况：信息没有进入记忆；进入后被压缩或替换；仍在记忆里却没被取出；已经取出但没有被正确使用。它们在最终回答中可能表现为同一种错误，但修复办法不同。

遗忘也应放在这个关系中理解。最近没有用过，不代表以后不会需要；内容重复，也不代表各次事件的时间与条件都相同。由此引出的学习问题是：保留多少信息，才能支持预期的未来任务？本综述提供分类和实例，没有给出一种对任意未来问题都最优的遗忘规则。

## 评价要区分记住事实、找到依据和完成任务

论文把评价分成直接评价和间接评价。直接评价尽量聚焦记忆机制本身；间接评价看带记忆的 Agent 在完整任务中表现如何。这个区别很重要，因为系统做对了，不必然意味着记忆环节正确；系统做错了，也不必然是记忆造成的。[论文 v1，§6.1–6.3](https://arxiv.org/html/2404.13501v1)

直接评价包含主观与客观方式。主观评价检查召回内容与上下文是否连贯、是否合理；它适合难以写出唯一答案的情况，但评审者和评分标准会影响结果。客观评价则涉及答案正确性、参考记忆的检索质量，以及时间和硬件成本。

其中，“答案正确性”与“参考准确性”尤其容易混淆。前者检查最后回答是否匹配目标答案，后者检查是否找到了应该使用的记忆。举一个教学例子：系统可能根据常识猜对答案，却没有取出指定历史记录；也可能取出了正确记录，但推理时把时间顺序弄反。因此，两项指标分别提供不同信息。

原文在参考准确性的讨论中使用 Precision、Recall 和 F1。Precision 关注取出的内容中多少真正相关，Recall 关注应该找到的内容中找回多少，F1 综合两者。它们依赖预先标注的相关记忆集合，不能自动判断一段生成解释是否忠实，也不直接衡量连续行动的质量。效率同样不能只看最后生成的耗时，还应区分写入、管理和读取的时间与资源消耗。[论文 v1，§6.1.2](https://arxiv.org/html/2404.13501v1)

间接评价覆盖对话、多来源问答、长上下文任务和其他任务，例如代码测试通过率或探索成果。它更接近实际用途，但模型能力、提示方式、工具和任务设置都可能影响分数。原文因此提醒不能把端到端改善全部归因于记忆；阅读实验时，应关注是否控制其他条件、是否比较去除或替换记忆后的表现。

v1 的作者还指出，当时缺少针对 Agent 记忆模块的专门开源基准。这是 2024 年该版本的领域判断，不能当作今天仍然成立的结论。本导读不提供当前方法排行榜，也没有复现或重新比较所引工作的实验结果。

## 应用改变了“好记忆”的含义

综述列出的应用包括角色扮演与社会模拟、个人助手、开放世界游戏、代码生成、推荐和领域专家系统。它们的区别有助于理解评价为什么不能只用一个统一分数：角色模拟关注背景与行为一致性，助手需要关联当前需求与先前交互，游戏强调经验和技能复用，代码任务需要连接错误、修改与验证反馈，推荐和专家系统则依赖相应的偏好信息或领域知识。[论文 v1，§7.1–7.7](https://arxiv.org/html/2404.13501v1)

作者在展望中进一步讨论参数记忆、多 Agent 之间的记忆协调、终身学习和类人 Agent。长期运行会放大时间关系、信息增长和遗忘的问题；多个 Agent 又涉及信息共享与不对称。类人模拟甚至不一定追求记得越多越好，因为研究目标可能要求模拟遗忘或知识边界。这些是作者提出的研究方向，并非已经由本文统一解决的能力。[论文 v1，§8.1–8.4](https://arxiv.org/html/2404.13501v1)

这份综述最适合提供一套继续阅读的坐标。面对下一篇记忆论文，可以先辨别它改变了来源、形式还是操作，再检查它的证据究竟证明了保存、检索、使用中的哪一项改善。持续环境中的判断修订、何时行动和计算分配，需要在这张地图之外继续学习，不能仅靠增加记忆容量回答。
