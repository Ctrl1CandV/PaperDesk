# 多智能体通信综述：谁在何时把什么交给谁

让几个语言模型互相说话，并不难；困难的是判断这些对话为什么有用。一个模型给出的信息可能被另一个模型忽略，也可能在反复转述后变成大家都接受的错误。即使最后任务完成，也还要分清收益来自更多推理预算、角色分工，还是通信机制本身。

《Beyond Self-Talk: A Communication-Centric Survey of LLM-Based Multi-Agent Systems》提供了一张以通信为中心的地图。作者先看系统层面的架构、目标与协议，再看系统内部的发言策略、交互范式、通信对象和内容。本讲解采用 arXiv **2502.14321v3，2026 年 5 月 26 日**版本，沿这些维度说明怎样阅读一个多智能体系统；它是主线讲解，不是逐篇被引工作的实验审计。[论文身份与版本](https://arxiv.org/abs/2502.14321v3)

## 从任务结果追回消息的作用

先设想一个教学情境：三个 Agent 合作修复文件解析器的边界错误。分析者提出故障位置，实施者修改代码，测试者检查输入样例。这里的角色和流程只是为了讲清概念，并非综述提供的实验。若测试者发现补丁失败，关键问题不只是它有没有发出消息，而是实施者是否收到对应补丁版本的失败证据、有没有据此修改，以及谁决定再次测试或停止。

这条因果链把“通信存在”与“通信有效”分开了。发送成功说明消息到达接口；对方准确理解说明语义得到保留；对方采取合适行动，才进一步关联任务推进。综述将通信视为连接各 Agent 的核心机制，但其分类本身不能证明某种连接一定改善结果。阅读具体论文时，应当寻找消息改变了哪一个决策，以及作者怎样检查这种改变。

本文的两层框架因此很有用：系统层回答谁能够连到谁、各方追求什么目标、如何互通；内部层回答什么时候发言、怎样组织信息、向谁表达、传递什么。它们是可同时描述同一个系统的不同维度，不是必须从左到右升级的阶段。[背景与系统通信入口](https://arxiv.org/html/2502.14321v3#S2)

## 架构决定信息能沿什么关系流动

图 3 把通信架构分为扁平、层级、团队、社会与混合五类。扁平结构强调节点之间直接交互，没有固定的上级统筹；层级结构将管理和执行分层；团队结构把不同任务或领域交给相对独立的组；社会结构强调更广泛环境中的规则、成员关系与互动；混合结构结合多种组织方式。作者的分类既涉及连接关系，也涉及组织角色，因此不能只凭节点数量判断属于哪一类。

回到解析器示例，三个 Agent 互相发消息，可以是扁平组织；由协调者把任务交给实施者、再交给测试者，更接近层级组织；若分别设解析与性能两个小组，又引入团队边界。允许所有节点互通，可能减少转交环节，却会增加需要筛选的消息；把消息集中给协调者便于形成统一安排，却可能让协调者的处理能力和判断成为瓶颈。这些是理解架构权衡的分析，并非图 3 给出的量化优劣排名。

读图时还要区分“允许连接”与“一次运行实际使用的连接”。设计图可以让任意两者通信，但某轮任务只需要测试者向实施者回报一个失败样例。前者是可用结构，后者是执行轨迹。要研究减少通信是否有益，必须看到实际发送的消息，而不能仅统计图上画了多少条边。[§3.1 与图 3](https://arxiv.org/html/2502.14321v3#S3.SS1)

## 共同目标与互通协议解决不同问题

综述将通信目标分成合作、竞争与混合，并在合作下进一步区分直接合作和通过辩论达成合作。这个划分提醒我们：发言形式激烈，不代表系统目标相互冲突。两个角色可以互相质疑，却仍为同一个正确答案服务。反过来，两个 Agent 即使礼貌交换信息，也可能各自争取有限资源。判断目标关系，要看各方被要求优化什么，而不能根据聊天语气命名。

这也解释了为什么不同综述会把“辩论”放在不同分类下。有的分类强调角色之间的局部竞争，有的强调最终共同目标。比较论文时应先写清分类层级，再看结论是否真的冲突。对于解析器任务，测试者提出反例，是为了帮助整个系统完成修复；若它的目标只是让实施者尽可能多次失败，任务机制便发生了变化。[通信目标](https://arxiv.org/html/2502.14321v3#S3.SS2)

协议则处理另一个层面的问题。本文讨论 MCP、A2A、ANP 等互通机制，用它们说明 Agent、工具或服务之间还需要约定接口、发现和交换方式。本讲解不把该版本的协议对照当作当前 API 文档，也不据此承诺采用某个协议就能安全、低延迟地完成协作。一个符合格式的消息仍可能指向错误的补丁、携带未经验证的结论，或者被接收者误解。接口互通与任务语义正确，必须分别检查。[协议讨论](https://arxiv.org/html/2502.14321v3#S3.SS3)

## 发言顺序改变了每个人看到的信息

图 6 比较逐个发言、同时发言和带汇总者的同时发言三种策略。逐个发言让后续 Agent 可以利用先前信息，但等待会累积，前面的错误也可能沿链条传播。在解析器示例中，如果实施者只接到分析者的错误定位，后面的测试就可能围绕错误位置展开。顺序带来信息依赖，不自动带来正确依赖。

同时发言减少逐个等待，允许不同角色并行提出判断，但它们可能基于不同步的状态作答。测试者检查旧补丁、实施者解释新补丁，两段话各自可能成立，合在一起却无法说明当前版本是否正确。因此，讨论并行策略时需要关心各方读取的版本与汇总时点，而不只关心速度。这里的版本例子是教学推演，对应原文关于状态陈旧与冲突解决的讨论。

加入汇总者后，并行输出先被整合，再传给后续环节。这可以减轻其他 Agent 阅读全部消息的负担，也把选择、压缩与冲突处理集中到了汇总者。如果它遗漏失败样例，简洁的报告反而可能消除重要异议。读相关论文时，可以追问：汇总保留了哪些原始依据，冲突如何呈现，后续 Agent 能否回到原消息核查？这些问题比“有没有总结”更接近通信的实际作用。[§4.1 与图 6](https://arxiv.org/html/2502.14321v3#S4.SS1)

## 消息、共享空间与行为信号如何承载内容

在发言顺序之外，作者用消息传递、言语行为和黑板系统描述交互范式。消息传递突出把内容送到特定对象或群体；言语行为突出一次表达的交互功能，例如请求、承诺或宣告；黑板系统让多个 Agent 通过共享空间发布、读取和更新信息。这些概念可以组合使用：测试者既可以向实施者发送失败结果，也可以在共享任务记录上标记“需要重测”。

共享空间并没有消除通信问题，只是改变了它出现的位置。如果一个 Agent 覆盖了另一个 Agent 的记录，或读取时没有区分旧状态，系统依然可能形成不一致判断。类似地，“我已经验证”是一次宣告，但这句话本身不等于可检查的测试记录。范式帮助我们描述内容如何进入协作过程，不能代替对内容来源和操作结果的验证。[通信范式](https://arxiv.org/html/2502.14321v3#S4.SS2)

作者又区分了与自身、其他 Agent、环境及人的通信，以及显式和隐式内容。自然语言、代码和结构化数据属于显式表达；行为反馈、环境变化也可能间接影响其他参与者。这里有两个容易混淆的边界：单个 Agent 的自我反思不因此变成多个独立 Agent；JSON 等结构化格式能约束字段，却不能保证字段里的断言正确。对于环境中的变化，也要区分 Agent 发出的信号与系统恰好观察到的变化，不能将所有相关性都解读成明确意图。[通信对象](https://arxiv.org/html/2502.14321v3#S4.SS3) · [通信内容](https://arxiv.org/html/2502.14321v3#S4.SS4)

## 评价应当检验通信带来的收益与代价

综述的评价讨论指出，仅报告个体正确率或最终任务得分，难以完整描述协调效率、消息带宽、时延，以及面对陈旧或欺骗消息时的鲁棒性。一个系统可能靠更多模型调用取得更高任务分数，同时花费明显更多时间与资源。另一个系统可能减少通信，却在需要跨角色整合证据的任务上失效。这些情况需要同时看任务结果和运行过程。[挑战与评价](https://arxiv.org/html/2502.14321v3#S5)

据此可以形成一组阅读方法，而不是假装本文已经给出统一实验答案：比较通信方案时，记录基础模型、可用工具、任务输入和预算；检查是否有单 Agent、多次独立采样、固定通信等适当对照；再看删减某条信息或改变发言顺序后，结果怎样变化。这里的对照建议是本讲解的分析延伸，不是综述已经完成的一组实验。

解析器例子也能说明过程评价为什么重要。修复成功率回答结果是否可用；消息数量和总耗时回答付出了多少；失败样例从测试者传到实施者并触发正确修改的比例，则尝试定位信息有没有发挥作用。最后一项是教学性诊断思路，尚未在此定义成正式基准。它的价值在于把“合作得很好”变成一个可以进一步操作化的问题。

## 把分类地图变成后续阅读条件

如果当前问题是“怎样组织 Agent 对话”，下一篇应优先选择明确给出角色、消息格式、轮转规则和结束条件的系统论文。若问题是“哪些通信可以删减”，则应选择报告结构选择或消息压缩机制、同时保留任务质量与成本对照的方法论文。两类文章都属于通信研究，但回答的问题不同，不能只因为标题含有 multi-agent 就视作同等相关。

阅读中可保留一条简短主线：系统需要交换什么信息；它通过什么关系与时序交换；接收者如何据此改变行动；作者用什么证据表明这种改变有益。已有的 Agent 总览帮助理解系统组成，本篇提供通信维度，而协作机制综述继续解释角色、规则和编排怎样组织这些维度。这样的顺序是编辑建议，不是原作者规定的课程。

还应把综述列出的开放问题当作检索入口。本文讨论了资源开销、语义理解、混合目标、互通、多模态与评价等问题，但“在综述中被列为挑战”并不等于在后续文献中仍未解决。要形成研究方向，需要再核查对应时间之后的具体方法、设置和失败条件。
