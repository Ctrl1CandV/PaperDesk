# Toolformer：工具调用怎样成为可学习的行为

如果模型已经可以调用计算器和检索系统，接下来的困难就不只是“有没有接口”，而是它能否在合适的位置发现信息缺口、写出有用的请求，并把返回结果用于当前任务。Toolformer 把这组决定放进语言模型训练：先产生候选调用，实际执行，再利用续写损失筛选训练材料。阅读它，可以把工具使用拆成可检查的数据、目标和执行过程。[主文 §1–2，PDF 第1–4页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf)

本文依据 NeurIPS 2023 正式论文与配套补充材料，讲清训练主线、关键筛选公式、主要实验及适用边界。它是一篇工具学习方法论文，不是完整的长程 Agent 方案；文中的历史成绩也不代表今天的模型排名。下文用独立教学例子帮助理解，不把例子当作论文实验。

## 工具提供能力，模型仍要决定如何使用

语言模型的基本工作是根据已有上下文生成下一个词元。计算器则按给定表达式运算，检索器按查询返回材料。把这些系统连起来，只解决了执行通道：它并没有自动教会模型何时应当停止续写、选哪个工具、参数如何表达，以及返回内容是否真正有用。

Toolformer 用文本表示调用及响应，使工具交互能够嵌入训练序列。可以把它理解成一段正文中插入了“请求—结果”，随后继续生成原文。推理时，运行程序检测到请求结果的分隔符，就暂停模型生成、执行对应 API，把真实结果放回上下文，再让模型续写。因此，返回值来自外部执行，不是让模型模仿一个看起来合理的结果。[主文 §2，PDF 第2–4页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=2)

论文使用五类工具：问答系统、Wikipedia 检索、四则运算计算器、向英语翻译的系统和返回日期的日历。问答工具直接给短答案，检索工具提供需要模型再提取的文本；两者不能仅因都“找信息”就视为等价。工具的响应形式和可靠性，会改变模型后续要完成的工作。[主文 §3，表1，PDF 第4页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=4)

## 从普通文本构造带有调用的训练材料

直接让人工标出大量调用位置、工具类型和参数，成本很高。作者的替代方案是给每种工具少量人工示范，然后让已有模型为普通文本提出候选调用。候选不是训练标签的终点；它们还要经过真实执行与筛选。[主文 §2，图2–3，PDF 第2–3页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=3)

候选生成包含两次选择。先估计哪些位置有较高概率开始一次 API 调用，保留达到阈值的有限个位置；再在每个位置采样若干请求。这样，训练材料不必事先被人工拆成“这是一道计算题”或“这是一道查知识题”。但它仍依赖人工定义的工具、示范、阈值及语料筛选规则。“自监督”描述的是大规模筛选信号的来源，不表示毫无人类设计。

一个教学例子是：“每盒有 24 支笔，买 7 盒共……”模型可以提出计算 `24*7`，也可能提出与续写无关的查询。执行只能告诉我们请求是否产生返回值；还需要另一个标准判断这个返回值是否值得写进训练数据。这个例子不是原论文样本，只用来说明生成、执行和筛选为什么必须分开。

```mermaid
flowchart LR
    A[普通文本与少量工具示范] --> B[采样位置与候选请求]
    B --> C[实际执行 API]
    C --> D[比较续写损失]
    D --> E[保留有用调用并插回文本]
    E --> F[语言模型微调]
```

这是对方法流程的教学示意，不是论文原图。箭头表达数据加工顺序：执行结果先参与筛选，保留的调用及结果随后成为微调材料，而不是在此时直接执行用户任务。

## 筛选目标：返回结果是否减少了续写的不确定性

设原始文本为 $x_1,\ldots,x_n$，候选调用位于位置 $i$。论文用下面的加权负对数似然衡量后续词元的预测难度：

$$
L_i(z)=-\sum_{j=i}^{n}w_{j-i}\log p_M(x_j\mid z,x_{1:j-1}).
$$

这里 $z$ 是放在上下文前面的辅助文本，$w$ 控制离调用位置不同距离的词元有多重要。损失越小，表示模型在这些条件下越容易预测原文中的后续内容。论文采用向近处衰减的权重，使筛选更关注调用附近的信息需求。[主文 §2、§4.1，PDF 第3、5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=3)

令 $e(c_i,r_i)$ 表示调用与实际结果的文本，$\epsilon$ 表示空序列。正例损失和基准损失分别是：

$$
L_i^+=L_i(e(c_i,r_i)),\qquad
L_i^-=\min\{L_i(\epsilon),L_i(e(c_i,\epsilon))\}.
$$

只保留满足 $L_i^- - L_i^+\geq\tau_f$ 的调用，其中 $\tau_f$ 是筛选阈值。这个最小值很关键：返回结果要比“不调用”和“只有调用、没有结果”两种基准中更好的一种还有效。否则，一个请求仅仅在措辞中透露了答案或提供了有利提示，也可能被误当成外部工具的贡献。

筛选时，调用信息作为前缀参与打分；训练时，再将保留的调用插入相应位置。两者不能混为一谈。原模型还没见过大量插入调用的文本，把调用直接塞入中间可能破坏原有分布，从而干扰损失判断，这正是论文选择前缀评分的原因。[主文 §2 及脚注2，PDF 第3页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=3)

从目标本身还能推出一个边界：降低原文续写损失，不等于证明调用内容真实，也不等于完成用户的长期目标。它是可自动计算的代理信号。补充材料确实列出返回内容无关却仍降低损失的例子。因此，理解方法时应当同时保留“能大规模筛出有用材料”和“筛选并非正确性认证”这两点。[补充材料 §E，PDF 第5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Supplemental-Conference.pdf#page=5)

## 微调、推理与零样本评测各有不同职责

筛选后，作者将调用及结果与原文合并，用普通语言建模目标微调模型。模型由此学习调用出现的位置、请求格式，以及拿到结果后的续写方式。主要实验使用 CCNet 子集与 GPT-J；正式论文将该底座记为 6.7B。这个标法只指论文中的主模型，不包含它可调用的 Atlas 问答模型等外部系统，不能据此把整套系统的成本算成单个底座。[主文 §2、§4.1，PDF 第4–5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=5)

数据加工还使用工具专属规则。例如计算器材料偏向包含数字与运算关系的文本，日历日期由文档 URL 中的日期近似得到，翻译材料则先寻找混有非英语片段的段落。这些规则影响了工具在哪里获得训练机会。补充材料也区分问答工具在构造训练集时使用 Atlas-large、推理时使用 Atlas-xxl，说明系统比较要把外部组件一起记入条件。[补充材料 §A.1，PDF 第1页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Supplemental-Conference.pdf#page=1)

论文的“零样本”是下游测试时给任务说明而不给该任务示例；模型此前已经接受过带工具调用数据的微调。它不等于从未训练工具使用。评测还做了两项干预：调用开始标记进入概率最高的十个词元时，就允许触发调用；每个输入最多调用一次 API。第一项提高调用倾向，第二项限制循环，二者都是理解成绩必须保留的条件。[主文 §4.2，PDF 第5–6页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=6)

## 对照实验把训练材料和实际工具调用分开

只比较 Toolformer 与未微调的 GPT-J，无法分清改进来自额外训练还是来自执行工具。论文因此加入用同一普通语料微调的 GPT-J + CC，以及已用调用数据训练、但测试时关闭 API 的 Toolformer。前者控制语料训练，后者帮助观察调用训练与测试时外部返回值的不同作用。

下表摘取主文表3的两个数学数据集，数值为论文所用判定规则下的正确比例（%）。这些都是论文的零样本提示设定；GPT-J 系列使用同一底座，Toolformer 开启调用时遵守前述单次调用和触发规则。判分取生成的第一个数字；若出现等式，则取等号后的第一个数字，不是对完整推理过程逐步评分。[主文 §4.1–4.2、表3，PDF 第5–6页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=6)

| 模型条件 | ASDiv | SVAMP |
| --- | ---: | ---: |
| GPT-J | 7.5 | 5.2 |
| GPT-J + CC | 9.6 | 5.0 |
| Toolformer，关闭 API | 14.8 | 6.3 |
| Toolformer，开启 API | 40.4 | 29.4 |

这组对照支持“在这些测试条件下，实际工具调用带来了额外收益”。它并不证明模型已经会做所有数学推理：即使计算器准确，模型仍可能选错运算或输入错误参数。也不能把关闭 API 后的改善全部归因为某一种内部能力，因为实验并未直接测量那种机制。

在问答任务中，作者关闭直接问答工具，用检索工具帮助回答，并以生成前二十个词是否包含正确答案来评估。Toolformer 改善了同底座结果，但在这些问答集上仍低于论文中的 GPT-3 175B 对照；MLQA 的表现也没有在所有语言上超过原始 GPT-J。方法的价值来自清晰的可学习机制及受控证据，而非“接工具后全面更强”。[主文 §4.2、表4–5，PDF 第6–7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=7)

## 工具价值取决于底座、反馈和任务边界

工具不是固定增益模块。如果底座已经能答出问题，一个噪声较大的检索结果反而可能分散注意力。补充材料用 LLaMA v1 7B 继续研究时发现，较强的直接问答工具仍能帮助知识填空，但弱的 Wikipedia 检索工具未给问答任务带来同样收益；生成和打分所用模型也会改变哪些调用被保留。这里更值得学习的是比较方法：工具价值应当相对于具体底座和任务测量，不能只看工具是否被成功调用。[补充材料 §G.2–G.4、表7–8，PDF 第7–9页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Supplemental-Conference.pdf#page=7)

“不损害语言能力”同样有条件。主文在关闭 API 的情况下测量 WikiText 和未用于训练的 CCNet 子集困惑度，Toolformer 与只用 CCNet 微调的对照相同；它没有证明任意能力都得到保持，也没有评估开放调用时所有可能工具路径的概率。[主文 §4.3 及脚注5，PDF 第8页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=8)

论文明确指出其方法不能形成可靠的链式调用，也不支持反复改写查询、浏览多项结果的交互式检索；候选调用独立生成，训练数据缺少前一工具结果进入后一调用的示范。此外，输入措辞会影响调用决定，生成有效材料可能低效，筛选目标没有计入不同工具的计算成本。这些限制使它更适合回答“如何学会有用的局部调用”，而不能直接承担完整 Agent 的持续规划与反馈学习。[主文 §6，PDF 第9页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=9)

## 回到原文与继续研究

若要真正掌握方法，优先读主文第3页的筛选式与脚注2，并自己说明为什么要同时与“空前缀”和“仅有请求”比较。接着读第6页表3和对应评测段落，练习把分数还原成模型、工具、触发策略和判分规则。若研究强模型的工具价值，再读补充材料 §G，尤其表8：对同一模型，工具的存在和工具的收益是两件需要分别测量的事。[方法与筛选，PDF 第3页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=3) [实验条件与表3，PDF 第6页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Paper-Conference.pdf#page=6) [补充表8，PDF 第9页](https://proceedings.neurips.cc/paper_files/paper/2023/file/d842425e4bf79ba039352da0f658a906-Supplemental-Conference.pdf#page=9)

一个可继续追问的问题是：若工具带来更低的续写损失，却增加延迟或给出错误信息，评价应如何同时记录收益与代价？这是由论文目标和局限引出的编辑性问题，不是论文已经验证的方案或研究空白。可结合 [HELM 的评价阅读](helm.md) 区分场景、指标和适配条件，也可回到 [Agent 综述](agent-survey.md) 判断工具学习在整个系统中承担哪一部分。本文没有复现实验，也没有逐条讲解全部提示、缩放实验或补充失败样本。
