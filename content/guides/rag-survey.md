# RAG 综述：把知识接入拆成可以检查的过程

一个语言模型回答错了事实问题，可能是没有相应知识，也可能是没找到材料、没有看见关键条件，或者已经看到材料却仍然错误推断。给模型连接资料库，并不会让这些问题自动变成同一个问题。学习检索增强生成，首先需要建立一条能区分失败位置的信息链。

Yunfan Gao 等人的综述把 RAG 组织为 Naive、Advanced 和 Modular 三种范式，再分别讨论检索、生成、增强过程与评价。本导读固定采用 2024 年 3 月 27 日的 arXiv v5，借这套框架解释各环节为什么需要独立检查。它补充原始 RAG 方法论文，帮助从一个具体模型走向系统设计；不是 2026 年技术与产品的完整清单。[论文身份与版本](https://arxiv.org/abs/2312.10997v5)

## 从一条信息链理解检索增强

先看一个教学例子：要回答某软件版本是否支持某项功能，系统必须取得对应版本的说明，找出有关功能与限制的段落，再据此作答。资料库里有最新版说明，并不意味着旧版本问题就能正确回答；检索到了同名功能，也不意味着限制条款一起被带入。回答是否有依据，取决于一连串选择。

可以用下面的教学示意追踪这条链。它概括本文的阅读视角，不是论文原图，也不表示所有 RAG 系统都采用相同实现。

```mermaid
flowchart LR
  D[固定版本的材料] --> I[整理与索引]
  Q[当前问题] --> R[检索候选]
  I --> R
  R --> C[选择并组织上下文]
  C --> G[生成回答]
  Q --> G
  G --> E[核对依据与任务结果]
```

索引决定什么可以被找到；检索决定哪些材料进入候选；上下文组织决定模型实际看见什么；生成决定如何使用这些信息。原文 §II-A 的基本流程是索引、检索与生成，§III–IV 再展开环节内部的选择。[基本流程](https://arxiv.org/html/2312.10997v5#S2.SS1)

这与“训练模型记住更多知识”有不同的操作位置。检索时改变外部材料，通常不必因此更新生成模型参数；但系统完全可以另外训练检索器或生成器。把检索和微调理解成互斥方案，会掩盖到底哪个部件发生了变化。

## 三种范式是在比较组织方式

综述的 Naive RAG 是基本检索—生成链；Advanced RAG 加入检索前后优化；Modular RAG 强调模块替换、路由和流程重组。图 3 显示，后者能容纳前两者，并非三套绝不相交的算法。[§II 与图 3](https://arxiv.org/html/2312.10997v5#S2)

理解这一区分，可以沿同一个教学问题逐步改变系统。最初把问题直接用于检索，再把结果交给模型；发现问法和文档术语不一致，于是加入查询改写；发现候选过多，于是增加重排与筛选；若问题有时需要查表、有时需要读说明，再增加不同来源的路由。每次改变应对应一个已观察到的缺口，而不是因为名称听起来更先进。

三范式也不能当作性能阶梯。“多了模块”只说明系统多了一项能力或决策，尚不能说明净收益。改写可能引入错误假设，重排可能淘汰重要反例，路由可能选错数据源。比较方案时，需要在同一任务、同一材料和可比较预算下检查这些变化。

## 检索粒度决定了信息怎样被切开

综述 §III 从来源、粒度、索引、查询、表示和适配器组织检索方法。读这一部分时，最有用的起点是“回答所需的最小完整依据是什么”。[检索章节](https://arxiv.org/html/2312.10997v5#S3)

例如，实验表格中的一个数字通常不能单独成为依据。它还依赖列名、数据集、实验划分与脚注。若切分只保留“83.2”，检索即使精确命中也无法恢复含义；若保留整篇文章，模型又要从大量无关内容中找到条件。粒度的选择因此同时影响可检索性与解释完整性。

一种教学上容易理解的折中，是用较短片段定位，再连同相邻上下文供阅读。也可以用章节、日期或文档类型限制候选范围。但元数据不是天然正确的：把上传时间当成发表时间，或把更新后的文件沿用旧版本标签，会让筛选在一开始就排除正确来源。

查询改写改变的是搜索表达，不应偷偷改变问题。假如问题是“方法在哪些条件下失效”，改成“方法如何提高性能”就可能只召回正面证据。检查改写是否保留否定、时间、对象和比较条件，往往比单纯增加同义词更有价值。

## 找到材料以后仍要检查如何使用

检索得分表示某种匹配关系，不是材料真实性或结论支持度的证明。重排与上下文压缩也有不同职责：前者调整候选次序或取舍，后者减少进入模型的信息量。综述把上下文整理和生成模型微调分别列在 §IV。[生成与上下文整理](https://arxiv.org/html/2312.10997v5#S4)

延续版本说明的例子，检索可能同时返回旧版限制和新版功能。如果压缩把“仅新版支持”删掉，答案会流畅而错误；若直接拼接两份材料，却不给版本身份，模型也可能把它们合成不存在的共同结论。压缩后的短文本需要保留决定判断的限定词、归属与矛盾，而不能只追求缩短比例。

因此，检查一次回答时可以顺着实际输入回溯：必要材料是否进入候选，是否最终进入上下文，是否被正确解释。三个问题对应不同改进方向。回答错了就更换生成模型，或者检索命中了就判定系统可靠，都跳过了中间环节。

## 多次检索要有明确的控制依据

综述 §V 区分迭代、递归与自适应检索。图 5 分别强调重复检索与生成、细化问题、以及判断是否需要检索和何时停止；它们描述的是控制过程。[§V 与图 5](https://arxiv.org/html/2312.10997v5#S5)

可以把“比较两个版本的接口迁移风险”作为教学情境：第一次检索找到两版说明；若仍缺迁移条件，就根据缺口继续检索；若问题太宽，先拆为兼容性、输入变化和错误处理，再分别调查。这些动作可以组成同一流程，不能只根据调用了几次搜索就断言属于哪种能力。

多轮流程最需要防止错误自我延续。第一轮生成的猜测如果被原样用于下一轮搜索，可能反复找到支持猜测的材料。每一轮应说明新增了哪条外部依据、解决了哪个缺口；没有新增证据时，应区分继续检索、缩小结论与停止。这里是教学检查方法，不是本综述证明的最优停止策略。

这也提供了通往 Agent 的连接：把检索看成可以选择和调用的工具，控制器决定何时用它。不过，拥有这一工具并不等于已经具备完整任务规划、环境操作或长期记忆。后续可用 ReAct 对照“检索—生成循环”与更一般的“行动—观察循环”。

## 把检索、依据和答案分别评价

综述 §VI 分开检索质量与生成质量，并讨论上下文相关性、回答忠实性、回答相关性，以及噪声、缺失依据、信息整合和错误材料等测试条件。表 III 同时说明，这些指标尚非统一成熟的标准。[评价目标与能力](https://arxiv.org/html/2312.10997v5#S6)

三个问题可以帮助读懂一次测量。第一，系统有没有找到需要的证据？第二，答案有没有得到已提供材料的支持？第三，答案有没有回答原问题并符合外部事实？这三个答案可能不一致。系统可以找到正确材料却误读，也可以忠实复述错误材料，还可以凭模型已有知识答对但没有给出支持它的证据。

为避免把这些现象混成一个分数，可以构造几种教学测试：提供充分依据、只提供部分依据、混入同主题但不支持结论的段落、加入相互冲突的版本。然后分别看来源选择、是否承认不足、结论与条件是否匹配。这样的测试设计解释了为什么需要多个评价面，不能被当作已经运行过的实验结果。

若由另一个模型评分，还应保存评分标准和具体判例。评价器的流畅判断并不消除误判可能；文本相似度也不天然等于事实正确。对影响结论的样本回看材料，仍是解释分数的重要步骤。

## 怎样把综述转成下一篇阅读

这篇综述最适合作为方法定位地图。阅读新 RAG 论文时，先写清它改变的是材料、检索表达、候选排序、上下文、模型参数还是调用流程，再找相应实验是否隔离了这一变化。若方案同时改动多个组件，端到端提升只能先归于整体系统，不能直接归因于其中一个模块。

基础阅读可先回到原始 RAG，理解检索结果怎样参与生成概率；再用 ReAct 认识何时把检索作为行动。这个顺序是编辑建议，不是作者证明的先修关系。综述 §VII 的长上下文、鲁棒性、混合训练等讨论可用于提出比较条件，不能把 2024 年列出的挑战直接宣布为当前研究空白。[讨论与未来方向](https://arxiv.org/html/2312.10997v5#S7)
