# Agent 综述：理解大模型怎样进入环境并持续行动

《A Survey on Large Language Model based Autonomous Agents》整理的是一类系统：它们把大语言模型放到持续的任务过程中，使模型能够利用信息、安排步骤，并通过行动与环境发生联系。作者从系统构建、应用和评价三个方面组织已有研究。读这篇的主要收获，是理解这些系统为什么需要不同组成，以及这些组成怎样共同工作。[原文 v7，§1–2](https://arxiv.org/html/2308.11432v7)

它适合作为当前的一个入口。你暂时不必选择专门研究记忆、规划或多智能体，但需要知道这些词分别在解决什么问题。这样，以后接触一篇具体论文时，才能把它放回较大的知识结构中，而不是每遇到一个新方法都重新开始。

以下以2025年3月的固定版本为阅读对象，讲解其主要脉络。版本日期不等于全文文献截止日；它提供一个理解框架，不代表截至2026年的全部进展。

## Agent 的基本视角：主体、环境与行动

Agent 通常译为智能体。先从一个功能性的定义进入：主体接收环境中的信息，据此采取行动，而行动可能影响环境和后续获得的信息。环境既可以是现实空间，也可以是网页、软件工具或模拟世界。教材中的经典 Agent 框架早已用感知与行动连接主体和环境，因此 Agent 并不是大模型时代才出现的概念。[AIMA 第2章材料](https://aima.cs.berkeley.edu/4th-ed/slides-pdf/chapter02.pdf)

这个视角改变了我们观察程序的方式。对于一次问答，注意力常集中在最后一句回答；对于持续任务，还要关注系统能观察什么、允许做什么、怎样根据结果改变下一步。一个系统可以只根据规则作简单反应，也可以利用模型、内部状态和计划作选择。是否采用大模型，与是否从 Agent 的角度组织系统，是两个不同问题。

大模型带来的新条件，是用同一类模型处理自然语言要求、已有知识和多种任务描述，并把它作为系统中提出下一步行为的重要部分。但语言能力不会自动把工具接好、把过去的经历存起来，或保证长任务成功。本文因此先研究构建方式，再讨论这些系统能用于什么、如何评价。[综述 §1](https://arxiv.org/html/2308.11432v7#S1)

## 四个组成部分，分别回应持续任务中的不同需要

综述用角色设定、记忆、规划和行动归纳系统架构。它们是理解已有工作的四个观察位置，不是要求所有 Agent 都必须装齐的清单。原文[图2，PDF 第4页](https://arxiv.org/pdf/2308.11432v7#page=4)是一张分类总图，也不应被读成四个模块按从左到右只运行一次。

### 角色设定使行为有具体背景

角色设定说明系统以什么职责或人物背景参与任务。作为助手时，它可能需要明确工作范围；在社会模拟中，则可能需要人物的经历、性格和关系。相同信息对不同角色的意义可能不同，角色也会影响系统关注哪些记忆、怎样安排活动。

所以，这一部分的研究不只是写一句“你是一位专家”。还涉及需要提供哪些信息，以及这些信息怎样生成、怎样在持续行为中保持作用。提示里有一个身份，也不能证明模型已经具备对应专业能力。[综述 §2.1.1](https://arxiv.org/html/2308.11432v7#S2.SS1.SSS1)

### 记忆让过去发生的事能够参与当前决策

单次输入的容量有限，长任务又会产生大量历史。系统若每次都从头开始，就可能重复操作，忘记先前约束，或失去已经得到的线索。记忆首先要解决的，就是哪些信息应保留、以后什么时候重新取出。

可以从三个不同维度理解它。结构上，系统可能把当前任务中的工作信息与较长期的记录分开；存储时，可以使用自然语言、数据库等形式，也可以通过向量表示支持匹配；操作时，则需要写入、检索，以及对经历进一步整理。短期与长期讨论保存和使用的组织，自然语言与向量讨论表示方式，它们不是同一张互斥分类表。

“检索”也不只是把所有历史重新塞进提示。系统要根据当前需要，挑出可能有用的记录，再让这些记录参与后续生成。某条经历被概括成更一般的经验，还增加了推断这一步；概括可能有用，也可能记错或概括过头。记忆管理因此与信息选择和错误传播相连。[综述 §2.1.2](https://arxiv.org/html/2308.11432v7#S2.SS1.SSS2)

一个可帮助理解的代表工作是 Generative Agents：它保存经历，提取更高层次的反思，并在安排后续行为时检索相关信息。这说明记忆的价值来自“保存—组织—再使用”的关系，不只是存储容量。这里仅借用原论文概述说明思路，不比较其实验表现。[Generative Agents 原论文摘要](https://arxiv.org/abs/2304.03442)

### 规划把一个目标展开为可能执行的步骤

规划需要处理目标与行动之间的距离。有些任务可以直接采取一步行动，复杂任务则可能需要先分解子目标、比较几条路径，或者把形式化约束交给外部规划器。综述也把一些单路和多路推理方法纳入讨论，但在环境中安排行动比“多写几步推理文本”涉及更多条件。

尤其需要区分预先安排和根据反馈修正。网页返回空结果，说明刚才的检索可能需要改变；工具报告执行失败，可能需要调整参数或换方法。环境反馈、人类纠正和模型自评来自不同信息源：模型说“这一步应该成功”，并不等于环境已经确认成功。[综述 §2.1.3](https://arxiv.org/html/2308.11432v7#S2.SS1.SSS3)

ReAct 提供了一种便于理解的思路：把文字推理与任务行动交替组织，行动带回新的信息，推理再据此更新下一步。这一例子说明为什么规划可以是持续过程；此处不要求先精读 ReAct，也不据其概述推断所有 Agent 都应采用同一流程。[ReAct 原论文摘要](https://arxiv.org/abs/2210.03629)

### 行动让系统的决定产生后果

行动是系统能够实际做的事，可以是执行工具、与其他主体沟通、探索环境，也可以是输出任务结果。需要交代的是可用动作、动作的生成方式，以及执行后影响了什么。

例如，生成一段“准备搜索文献”的文字，只表达了意图；真正调用检索接口并收到结果，才建立了与环境的联系。又如，工具返回一个错误信息，这个结果本身仍是有用观察，不能被系统当作已经完成任务。综述把行动的目标、产生方式、空间和影响分开讨论，正是为了把这些层次看清。[综述 §2.1.4](https://arxiv.org/html/2308.11432v7#S2.SS1.SSS4)

## 把组成连接起来，仍要解释能力从哪里来

现在可以用一个辅助情境串起前面的概念。假设一个阅读助手要整理某个主题的候选论文：角色与任务要求规定选文范围；记忆保存已查过的文章和排除理由；规划决定先搜索、再筛选、再补充遗漏；行动完成检索和打开材料；返回的信息又影响下一轮选择。这是教学示例，不是综述报告的实测系统。

```mermaid
flowchart LR
    A[任务与角色背景] --> B[结合当前观察和相关记忆]
    B --> C[安排下一步]
    C --> D[执行动作]
    D --> E[环境返回结果]
    E --> B
```

这个流程解释了各部分怎样连接，却还没有回答：为什么模型能作出有效选择？因此作者把“能力获取”与“架构设计”分开。架构说明怎样组织，能力获取讨论如何使任务表现得到改善。

一种方式是微调主体大模型，用训练数据更新它的参数，使其更适应所需行为。另一类方法不微调所使用的主体大模型，通过提示、示例、反馈与工作流程组织已有能力。这一区分不能外推为整个系统的所有辅助模型都不训练；后者也可能随着执行而积累记录、改变下一次输入，“主体模型参数没有变”不等于“整个系统状态没有变”。[综述 §2.2](https://arxiv.org/html/2308.11432v7#S2.SS2)

这一区分会贯穿后续阅读：读到一种新方法时，要看它改了模型内部参数，还是改了模型在任务中获得的信息和行动过程。[InstructGPT](instructgpt.md)主要帮助理解前一类改变；本篇则把它放回更大的系统构建问题中。这个连接是阅读上的组织方式，不表示 InstructGPT 本身是一篇 Agent 系统论文。

## 应用不同，“做好了”的含义也不同

综述讨论社会科学、自然科学与工程中的应用。分类本身不需要背诵，值得理解的是，不同任务会改变系统需要保留的信息、允许采取的行动和成功标准。

社会模拟关心角色行为是否符合被模拟的人及环境；工程助手可能更关心任务是否正确完成、失败能否被发现；科学辅助则还需要把提出的想法接到实际验证上。综述中的应用实例说明研究者尝试了哪些方向，不能直接作为系统已经可靠部署的证明。[综述 §3](https://arxiv.org/html/2308.11432v7#S3)

评价也因此不能只有一种。人工判断适合检查某些难以自动定义的表现，但会受判断标准影响；自动评价有助于重复比较，也需要看它测量的是否正是任务目标。本文在客观评价中区分指标、评价协议和基准：指标规定量什么，协议规定怎样执行比较，基准提供任务或环境。任务成功率、行为可信度与运行成本回答的是不同问题。[综述 §4](https://arxiv.org/html/2308.11432v7#S4)

当一个系统看起来“很会行动”时，下一步便可以具体观察：它是否完成目标，过程是否稳定，又付出了什么代价。这些判断之所以现在可以提出，是因为前面已经建立了系统与任务的关系。[HELM 导读](helm.md)会进一步展开评价设计的思路，但其模型评测结果不能直接替代 Agent 的交互任务评价。

## 开放问题来自这些组成之间尚未解决的矛盾

作者指出，模型可能难以准确模拟少见角色及某些认知心理特征；提示变化、幻觉和多次模型调用带来的效率问题，也会影响系统表现。[综述 §6.1、§6.3–6.4、§6.6](https://arxiv.org/html/2308.11432v7#S6)把这些挑战接回前面的结构，还可以进一步追问：错误若被保存在记忆中，会不会持续影响后续行动？增加规划和反思，带来的收益是否值得额外成本？后两个问题是本导读对组件关系的延伸分析。

另有两项挑战特别依赖应用语境。社会模拟若要反映不同人的价值观，一个按照较统一的行为准则训练成助手的模型未必自然保留这种差异。类似地，模型知道的知识可能远多于被模拟人物，造成行为失真；这正是本文“知识边界”讨论的重要含义。把它笼统改写成“模型还需要更多知识”，就会错过作者的问题。[综述 §6.2、§6.5](https://arxiv.org/html/2308.11432v7#S6)

这些是固定版本提出的研究问题。判断其中某一项截至今天解决到什么程度，需要再检查后续原始研究，不能仅依据这篇综述宣布它仍然全无进展。

## 这篇怎样成为以后阅读的起点

读完后，知识结构可以先保持简单：Agent 与环境持续发生联系；模型是系统中的重要部分；角色、信息保存、规划和行动提供几个观察角度；系统能力还受训练与运行组织影响；最终需要回到任务中评价。

以后读到一篇具体工作时，可以先找到它改变了其中哪一处，再理解为何这处改变可能有用。某个问题反复引起你的兴趣，或者不同论文对同一条件给出不同结果，才值得逐渐多读几篇，形成更具体的问题。当前无需从组件名单中立刻选定研究方向。

若愿意留下积累，可以用一段自己的话解释“语言模型”与“包含它的 Agent 系统”之间的关系，再记下一个仍想深入的连接。图2或本导读可以帮助回忆，但理解的目标不是背出四个模块名。

## 哪些原文值得亲自读

当前若只是建立领域框架，可以先停在这份导读。若要选择一个最值得对照的原文位置，建议看[图2及紧接着的说明，PDF 第4页](https://arxiv.org/pdf/2308.11432v7#page=4)：关注四个组件下分别采用哪些分类维度，再与前面的解释对照，不必立即读完每个组件的全部代表工作。这有助于形成以后放置新论文的框架。

以后想弄清系统怎样获得能力时，再读 [§2.2](https://arxiv.org/html/2308.11432v7#S2.SS2)，具体辨别哪些方法微调主体大模型、哪些通过运行过程组织能力；准备比较系统效果时，再进入 [§4 的评价](https://arxiv.org/html/2308.11432v7#S4)。这些是对应需要出现后的入口，当前不必顺次完成。
