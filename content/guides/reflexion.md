# Reflexion：把失败反馈变成下一次行动的经验

一次 Agent 任务失败后，重新发送相同要求，可能只会得到另一条相似的失败轨迹。《Reflexion: Language Agents with Verbal Reinforcement Learning》研究的是：怎样把一次尝试的过程和结果整理成可再次使用的文字经验，让下一次尝试带着具体的修正方向开始。它把行动、评价和反思组织成闭环，模型权重在这个过程中保持不变。[正式版 §1，PDF 第1–2页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf)

这篇适合接在 Agent 系统概览之后阅读：它让“记忆”和“反馈”从架构名词变成可以检查的工作过程。以下依据 NeurIPS 2023 正式版，解释主要机制、三类任务的证据及关键失败条件；它是有明确覆盖边界的研究主线阅读，不是当前 Agent 能力排名，也不包含实验复现。

## 改变的是下一次决策的上下文

理解 Reflexion，先区分两种“学习”。一种把新经验转为训练样本，通过优化更新模型参数；另一种把经验保存在模型之外，在下次调用时重新放入上下文。Reflexion 采用后者。论文里的“强化”强调行为会受到任务反馈影响，并不表示每次失败后都运行一次策略梯度或重新微调模型。[§3，PDF 第3–5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=3)

可以用一个教学记法表示这种关系：

$$
a_t \sim \pi_{\theta}(\cdot\mid q,h_t,m_k)
$$

这里，$q$ 是任务要求，$h_t$ 是本次尝试已经发生的行动与观察，$m_k$ 是进入第 $k$ 次尝试时保留的反思经验；$\theta$ 表示固定的模型权重。这个式子是对机制的教学概括，不是照抄原文公式。两次调用可以使用相同模型，却因 $h_t$ 和 $m_k$ 不同而提出不同动作。因此，判断系统有没有改进，不能只看参数是否变化，还要检查它实际上带入了什么经验。

这种区分也限制了结论。某个任务重试成功，说明带着反馈再尝试可能有用；它不直接证明模型已经普遍掌握同类任务，更不证明清空记忆后还能保持收益。论文主要检查同一任务经过若干次尝试的改善。将这种经验迁移到全新任务，是另一项需要实验的问题。

## 行动者、评价者与反思者怎样接起来

Actor 负责产生回答或动作。它可以使用逐步推理，也可以采用 ReAct 那样的行动—观察轨迹。Evaluator 判断本次输出或轨迹是否满足任务条件；实现可以是环境信号、规则、答案匹配或模型参与的评价，并不要求三个角色各自对应一个单独训练的大模型。Self-reflection 再根据轨迹、评价和已有记忆，生成下一次可用的经验。[§3 与图2，PDF 第3–5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=4)

三者处理不同的问题。“失败了”是评价，却还没有告诉行动者应该改哪一步。反思尝试补上这一层：哪条假设可能错误，哪一步没有取得预期观察，下次应先核查什么。它的作用是把稀疏结果转成可操作的修改方向，而不是把负面分数换一种措辞再说一次。

把完整轨迹再次交给行动者，与先生成反思再交给它，也不是同一个操作。前者保留更多现场细节，却让行动者同时承担诊断和重做；后者先选出认为重要的关系，减少再次寻找关键错误的负担，却引入摘要失真。论文在 HotpotQA 的消融中比较了保留最近轨迹与增加反思的设置，因此，“有记忆”还不足以说明记忆内容怎样影响行为。[§4.2 消融说明，PDF 第7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=7)

下面是按职责关系重绘的教学示意，非论文原图：

```mermaid
flowchart LR
  A[任务与保留经验] --> B[Actor 产生行动轨迹]
  B --> C[Evaluator 检查结果]
  C --> D[失败时分析轨迹与反馈]
  D --> E[保留可用反思经验]
  E --> A
```

图中只展开失败后继续尝试的支路。成功或达到预定尝试上限时应结束，而不是无限循环。当前轨迹承担短期记忆，跨试次保存的反思承担较长期的经验；论文为控制上下文长度，通常只保留少量最近经验，ALFWorld 和 HotpotQA 设置中保留最近三次，编程设置保留一次。[§3–4.1，PDF 第5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=5) [§4.3，PDF 第7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=7)

例如，设想一个教学任务要求先取得工具再处理物体。系统把“我打算取得工具”误当成“已经取得工具”，后续操作便可能连续失败。有价值的反思应指向缺少的环境确认，并提醒下一次先核实持有状态。这是机制示例，不是新增实验结果。文字经验始终是一种解释；即使写得很具体，也需要后续行动与观察来检验它。

## 不同实验提供了不同强度的反馈

Reflexion 的评价条件随任务改变，不能把它们合并成“模型只靠自省就提高了”。在 ALFWorld 中，环境可以报告任务完成，规则还能识别重复无效动作和过长轨迹；失败后重置环境再尝试。在 HotpotQA 中，系统在试次之间获得与标准答案精确匹配产生的成功或失败信号。它不拿到标准答案文本，但这个判定仍依赖基准提供的答案，并非在开放问答里凭空可得。[§4.1–4.2，PDF 第5–6页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=6)

编程实验则让模型生成内部单元测试，运行代码得到反馈，再据此修改。语法检查筛掉不能解析的测试，每个测试集最多使用六个测试；这能提供比单一失败标记更具体的信息，但生成出来的测试并不天然正确或充分。[§4.3，PDF 第7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=7)

以下只选取有助于理解条件的结果，不把它们当作跨任务排行榜：

| 实验位置 | 原文设置与观察 | 应当怎样理解 |
|---|---|---|
| ALFWorld，§4.1、图3 | GPT-3 作为语言模型、ReAct 行动者；134 个环境，经过12次连续试次，规则评价的 Reflexion 组合完成130个任务 | 图中是随试次累计解决的任务比例，不是首次尝试成功率 |
| HotpotQA，§4.2、图4 | 100道问题，分别比较检索式 ReAct、CoT 及提供标准支持上下文的 CoT；试次间有答案匹配反馈 | 有无检索、有无标准上下文和有无反馈是不同条件，不能只归因于“反思”二字 |
| HumanEval Python，表1 | GPT-4 基础方案80.1%，Reflexion 方案91.0%，原文报告 pass@1 | 最终提交前可以生成测试、运行和反复修改；不等于只调用模型一次 |
| MBPP Python，表1 | GPT-4 基础方案80.1%，Reflexion 方案77.1% | 加入反思流程没有保证所有数据集都改善 |

结果来源为[图3–4及实验说明，PDF 第5–7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=6)和[表1，PDF 第7页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=7)。这些是论文当时的模型、任务和流程结果，不表示当前模型水平。

尤其要认真读 pass@1。这里内部测试用于改进候选程序，最终程序再交给基准的隐藏测试判定；因此论文仍以最终提交的通过情况报告这一指标。它没有把内部修改过程变成“一次无反馈生成”。比较方法时，还需要考虑模型调用次数、测试执行、尝试上限和 token 成本；表里的两个百分数本身不能证明等预算下的优势。

这还提醒我们区分停止条件与评价标准。内部反馈决定系统是否继续投入一次尝试，外部基准决定最终提交是否正确。若两者完全相同，试错可能直接利用评测答案；若两者不同，系统又必须承担代理反馈与真实目标不一致的风险。读一条提升结果时，先把这两个位置标出来，比只比较百分数更能说明该方法能否迁移到实际任务。

## 反馈错误时，反思也可能放大错误

内部测试把一个错误程序判成通过，系统就可能过早停止；测试本身写错，则可能把正确程序判为失败并诱发无用修改。论文表2专门分析这种评价错误，而不是把内部通过率直接当成真实正确率。MBPP Python 的负面结果说明，测试质量与反思能力必须放在一起看。[§4.3、表2，PDF 第8页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=8)

作者还在由 HumanEval 转成 Rust 的50道困难题上做了消融，使用 GPT-4：基础方案60%，省去测试生成但保留反思为52%，省去反思但保留测试为60%，两者都有为68%。这些数字针对这个子集，不能外推成所有代码任务的固定增益。它们支持一个更具体的判断：在该设置中，评价材料与把材料转成修改方向的过程，需要协同工作。[表3及消融说明，PDF 第8页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=8)

这里存在一个容易忽略的边界：反思文本给出的是对失败原因的推断。一次失败可能有多种原因，模型也可能把偶然变化解释成规律。因此，可读的反思比完全看不到中间信息更方便诊断，但“能读懂说明”不等于“已经验证因果关系”。检验经验是否有效，仍要回到行动结果及恰当对照。

## 经验记忆的价值与失效边界

把长轨迹压缩成少量经验，可以让下一次尝试更容易注意到关键错误；代价是压缩会丢失细节。只保留最近经验还可能忘记更早的约束。论文的滑动窗口是一种具体实现，不能直接等同于可无限积累、稳定检索、跨任务通用的长期记忆系统。[§3 与 §5，PDF 第5、9页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=9)

更明确的失败例子在附录 B.1。作者用两示例 ReAct 加 Reflexion 在100个 WebShop 任务上试验，四次试次后没有观察到改善迹象而停止运行。作者认为需要更有多样性的探索时，反思可能困在原有解法附近；这是一组特定任务和配置的失败证据，不足以证明所有网页任务都不能受益。[附录 B.1 与图6，PDF 第14页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=14)

所以，接入 Reflexion 前值得依次检查：失败信号是否可信，系统是否能定位可修改的行为，环境是否允许重试，下一次是否真的能执行不同方案。若只能反复产生措辞不同的解释，却没有更好的观察或行动选择，经验缓冲区可能只是储存了重复判断。

从研究阅读走向探索，可以比较“只重试”“重放完整历史”“保留压缩反思”三个条件，并控制同一基础模型、总尝试预算和评价信号。观察错误是否减少、成功是否迁移到新任务，再讨论记忆机制的价值。这是由本文提出的编辑性比较思路，不是已验证的新研究缺口；[HELM 的评价阅读](helm.md)可帮助继续检查指标与条件的对应关系。

## 哪些原文值得亲自读

先看[图2与 §3，PDF 第4–5页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=4)，沿着轨迹、评价、反思、记忆找出每种信息的来源。重点辨别“谁生成经验”和“谁提供判定”，不要只记住三个组件名称。

随后看[图3–4，PDF 第6页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=6)，先读横轴的试次和纵轴的累计比例，再比较曲线。编程方向则重点读[表1–3与 §4.3，PDF 第7–8页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=7)，把最终正确率、内部测试误判和消融条件分开理解。

最后读[§5 与附录 B.1，PDF 第9、14页](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf#page=14)，用失败案例修正对“自我改进”的直觉。本文未逐项展开全部任务轨迹、提示模板、不同语言实现和代码参数，也没有重新运行实验；复现或严格预算比较需要进一步核对作者实现。需要先补齐系统视角时，可返回 [Agent 综述](agent-survey.md)；这里的先后关系是阅读建议，不是实验上的因果结论。
