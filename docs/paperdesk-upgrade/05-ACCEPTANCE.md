# PaperDesk 升级验收与质量验证

## 1. 验收范围与基准

审阅基准为 PaperDesk 提交 `1668527a9e84cacac85019c569f44719bb90252d`。该版本有 14 篇当前导读、18 个保留修订；已具备导读版本校验、来源快照、事务存储、请求幂等、并发控制和流式恢复。真实模型回答质量、扩容性能与长期稳定性尚未获得充分验证。依据与代码定位见 [07-SOURCES.md](07-SOURCES.md)。

**本文全部新增指标都是拟定的开发验收门槛，不是已经测得的性能，也不构成学术可靠性保证。** 实施时先记录实际起点提交；若它已晚于上述基准，审查差异，保留已经完成的改进。本文只约束 PaperDesk，不能据此修改 grad-companion-plugin。

内容按 [01-CONTENT-WORKFLOW.md](01-CONTENT-WORKFLOW.md) 复核，来源与图表按 [02-SOURCES-AND-VISUALS.md](02-SOURCES-AND-VISUALS.md) 核验；工程实现按 [03-AI-DATA-IMPLEMENTATION.md](03-AI-DATA-IMPLEMENTATION.md) 与 [04-CODEX-TASKS.md](04-CODEX-TASKS.md) 执行。每项结果只能标为“通过、失败、未验证、不适用”，其中“不适用”须有范围依据。模拟服务、真实原文核查和真实模型调用分别记录；缺少其中一种证据，不能拿另一种代替。

## 2. 结构、阅读与既有行为

### 2.1 必须保留的契约

| 编号 | 最小验证操作 | 通过条件 |
|---|---|---|
| C01 内容兼容 | 加载现有 guide v1/v2、catalog、library briefs；打开所有当前修订及保留修订 | 原有内容仍可读；新字段通过明确版本/适配层接入，不放宽旧 schema 来吞掉未知字段 |
| C02 不可变内容 | 同修订重复导入；再修改正文、元数据或图片字节重试；切换推荐修订后回到旧链接 | 相同输入为 no-op；同修订变更被拒绝；`bodySha256`、旧修订及稳定 unit 定位保持有效 |
| C03 个人记录 | 用合成记录覆盖旧 unit 笔记、引文、进度、导读/原文阅读标记和探索记录；更新内容后回放 | 不自动迁移或覆盖用户原话；缺失目标显示未解析并保留快照；打开文章不等于读完或掌握 |
| C04 阅读界面 | 在生产构建检查综述和研究论文的导读、深读、来源跳转、AI 开合及返回位置 | 保留用户认可的完整自然段、直接可见内容与阅读宽度；不把主要信息改成大量碎句或折叠面板 |
| C05 问答保护 | 重复 requestId、同会话并发、两个活动请求、第三请求、取消、超时、断流、空终态 | 幂等不重复推理；锁可释放；部分答案可恢复；预算耗尽有明确结果，不静默删证据后冒充完整回答 |
| C06 授权与服务切换 | 使用合成授权/错误覆盖登录、模型缓存、权限失效、目录重试、额度 fallback | 密钥留在后端；未授权不推理；只有已支持的明确额度错误触发配置允许的 API fallback；切换不丢来源或旧片段 |
| C07 流式与来源 | 交错输出、最终文本修正、工具多轮、fallback、旧会话重新打开 | 最终文字与持久化一致；已保存编号仍指向当轮来源；未知引用不生成伪造链接 |

这里的“保留 limits”指保留每次请求、文本、工具、并发和传输的有界处理。解除 AI 历史的 16MiB 总容量耦合，不代表移除所有安全上限。个人记录扩容也在本轮范围：显式迁移IndexedDB布局，定义新版个人备份并兼容旧v1，不能只把5MiB常量调大而保留高频全库校验。

现有校验至少保留 `tests/content-validation.test.mjs`、`content-import.test.mjs`、`ai-runtime*.test.mjs`、`ai-fallback.test.mjs`、`chatgpt-*`，以及 records、ai-context、ai-connection、reader、library 相关浏览器测试。新增测试围绕真实风险，不照抄实现断言。阶段内运行受影响测试；集成完成后运行现有完整入口：

```text
npm run build
npm test
npm run test:e2e
```

这些命令证明的范围由实际测试决定。构建成功、模拟 125 条检查通过等历史结果，均不能继承为本次升级结果。测试使用隔离目录和合成私人记录，不读取实际凭据或私人笔记。

### 2.2 原文证据、图表与压缩边界

至少选择一篇综述、一篇方法论文、一篇含关键图表/公式的论文进行独立原文核查，允许与下文真实题集共用材料。夹具须覆盖 HTML、有印刷页差异的 PDF、复杂图、带脚注的结果表及公式。审阅者是 AI 或人工要如实记录，不能把 AI 检查写成人工审核。逐项验证：

- 原文来源有稳定论文身份、已核实的版本/日期或明确未知状态、文件 hash 和解析版本。章节 anchor 必须实际存在；找不到时退回可核查位置并注明粒度，不拼造“精确定位”。
- PDF 同时区分从 1 开始的物理页序号与印刷页码，例如“PDF 第 8 页，文内第 6 页”。对跳转页和相邻页做视觉检查，不能只测 URL 含有 `#page=`。
- 图片保留原始像素宽高、来源页、图号及裁剪/缩放信息。实际查看像素并检查小字、坐标轴、图例与表格单元格可辨认；放大生成或 CSS 拉伸不算恢复原图细节。公式和表格不能仅凭 OCR 文本判定准确；`caption-only` 与历史 `figuresViewed` 不因摄取材料自动升级为本轮已核。
- 图表引用同时保留数据集、模型/设置、指标单位、比较基线、样本或误差说明等与论断有关的条件。裁剪不应去掉关键图例或注释；表格行列不可错配。
- 导读保留研究问题、核心方法、主要证据和适用边界；深读解释因果链、假设、实验与局限。没有覆盖的推导、负结果或附录须明确，不把“主线覆盖”写成“全文已核查”。
- 原文事实、阅读解释和研究推测有可辨识措辞。精简只删重复，不删使结论成立的条件。用户应能从关键结论回到证据，而无需阅读全部元数据。

`guide`、`original`、`web` 来源须明确区分。旧 `L…` 导读快照不因新增原文而自动升级为“原文证据”；网页摘要不能标为已读全文。删除或重建索引不得破坏历史问答来源快照，亦不得删除权威材料清单、证据映射、核验状态或手工纠错。原始HTML不能在应用同源执行活动脚本；展示副本的定位映射须验证。

## 3. 迁移、备份与中断恢复

在隔离副本构造以下夹具：旧 SQLite 布局及完整/中断/错误 turn；AI JSON 备份 v1/v2；个人备份 v1；带 fallback 片段与历史来源编号的会话；保留修订与已不存在 unit 的记录。用相同 fixture 比较迁移前后 ID、版本、引文、标记、来源文本、引用关系和终态，而非只比较总条数。

1. **升级和重复启动**：记录迁移前 schema 版本与可恢复备份；正常升级、再次启动、再次执行迁移均不重复写数据。来源扩展采用新版本和显式转换；v1/v2 旧数据仍可导入，不捏造缺失的原文定位、模型或来源身份。
2. **失败与 crash**：在迁移准备、事务写入、提交后确认、索引构建、索引切换处注入失败，特别覆盖“内容目录已经切换、索引事件尚未入队”。重启应根据目录摘要补齐遗漏任务，得到完整旧状态或完整新状态；不能是半迁移数据库、半套检索索引或永久 running 锁。事务回滚后旧数据仍可读。
3. **恢复与降级**：验证索引可从规范内容重建，正文和个人记录不是索引的附属品。数据库格式不兼容旧程序时，旧程序须拒绝写入；降级走已验证备份恢复流程，不能只把版本号改回去。保留升级后新数据的处理说明。
4. **大库备份**：正常使用可超过旧 16MiB 总量；新备份支持有界分页/分块，并有 manifest、格式版本、块序号、校验与一致性边界。导出期间有新写入时，输出要么来自一致快照，要么明确排队，不能混合时间点。
5. **导入原子性**：缺块、重复块、hash 不符、未知版本、ID 冲突、非法来源和中途取消均不产生部分可见记录。复原过程沿用冲突规则并保持可恢复；旧备份不为适配新格式而被原地改写。
6. **无副作用检查**：导入、迁移、回放、本地全文索引重建不触发回答生成或隐式联网，不改变授权选择、阅读标记或笔记。未来若启用需要外部 embedding 的索引步骤，应在其明确的配置与授权范围内执行并单列调用，不能混入普通导入。大库导入也不得默默绕过单条长度、来源和格式校验。

另做两条贯穿测试：其一，新工具取原文→ChatGPT中途额度fallback→API沿用相同证据→新版备份导出/恢复→新original与旧L/W会话共同回放；其二，一轮问答的搜索与补读之间发布新内容/切换索引，确认整轮仍固定原目录/索引/解析上下文，后续新轮才看到新版。模拟异常可验证程序行为，但不能表述为已证明物理断电、磁盘损坏或所有文件系统的耐久性。迁移造成数据损失、旧会话引用错位或无法从已验证备份恢复，均阻断交付。

## 4. 性能与规模验证

### 4.1 数据与测量方法

分别变化内容规模 **14 / 100 / 1,000 篇**与 AI 历史规模 **10 / 64 / 256MiB**，至少跑完整组合的本地检索、分页和 checkpoint 测量。100/1,000 篇可用明确标注的合成数据；覆盖不同长度、章节数、中英文术语、相似标题、保留修订和图表元数据，不用同一小文本复制后宣称验证真实论文质量。AI 历史夹具含来源和工具快照，不能仅填充无关字符。

同机、同构建、同数据种子对照，记录必要的 Node、应用、SQLite/检索器版本及数据量，不收集机器用户名、私人路径、环境变量或账号信息。每组预热后至少采样 100 次，报告样本数、p50/p95、错误率；另记冷启动、索引构建时间及内存峰值。保持相同并发规则，补测两个正常活动请求。

每组同时记录当前guide数、保留revision数、原文单元数以及正文/元数据/资产总字节。基线`catalog.currentRevisions`上限1000，`entries`上限10000，完整校验累计材料上限64MiB；补测1000/1001、10000/10001及64MiB边界。实施者明确哪些上限通过版本/配置调整、哪些仍保留为支持边界；不得关闭schema或去掉历史版本来假装扩容成功。

个人记录另建一份超过5MiB的合成库，覆盖续读保存、笔记编辑、两标签页冲突、备份导出/恢复和保存失败时草稿保留。普通写入不得读取全部object stores后重新校验整库；旧v1导入后的记录与新版大备份恢复保持等价。

旧版本若拒绝 64/256MiB，应记录“旧容量规则拒绝”，不能关闭校验制造可用基线。新版本须通过受支持的数据路径在隔离环境生成大库，验证**超过 16MiB 后仍可提问、保存和恢复**。

### 4.2 初始目标与结构约束

| 操作 | 初始目标 | 测量边界 |
|---|---|---|
| 本地检索 | warm p95 ≤ 500ms | 1,000 篇/256MiB 组合；含过滤、召回、排序和证据结果构造，不含远程模型 |
| 历史分页 | 每页 100 条，p95 ≤ 200ms | 固定大小的会话/轮次摘要；完整证据按需读取，不能把大快照隐含带回 |
| 流式 checkpoint | warm p95 ≤ 100ms | 包含本轮必要校验、事务提交与持久化；不以空操作替代 |
| 大库连续运行 | 无容量假死、丢失或引用错位 | 连续提问、工具返回、取消、重启及备份恢复；单轮/服务保护仍生效 |

常规写入不得 `snapshot()` 全部会话来重新核算容量；分页不得先全表读取再切片。检查 SQL/调用路径，并对 10→64→256MiB 的 checkpoint 曲线做比较：如接近按总库大小线性增长，应定位原因，即便某一档暂时小于 100ms 也不能视作结构问题解决。

远程 embedding、rerank、首字等待和完整回答耗时另列，区分供应商耗时、本地处理和排队。记录本轮输入/输出 token、证据数量及截断原因；提示预算要考虑实际模型 tokenizer 或有说明的保守估算，字符数不能假称精确 token。不得通过漏证据或缩短到无法回答来通过延迟目标。目标未达须提交测量和修复/范围调整理由，不能把目标改名为“已通过”；调整须留决策记录。

## 5. 最小真实学术问答集：30 题

这是**待建设与执行的验收集建议**。使用合法可获取且版本已固定的真实原文，题目不能仅从导读生成；至少覆盖综述、方法/实验论文、图表数据及原文与导读覆盖不一致的情况。

| 类别 | 数量 | 重点 |
|---|---:|---|
| 事实与数字 | 10 | 指标、单位、基线、实验条件和原文位置；包含表格/图注，避免全是摘要可答题 |
| 机制解释 | 6 | 关键概念、公式/变量、设计理由和适用前提；检查单篇讲解是否有完整逻辑 |
| 跨篇比较 | 4 | 两篇或多篇的共同维度、真实差异与不可直接比较的设置 |
| 资料不足 | 4 | 库内缺证据、只有导读、全文不含所求结论、证据冲突等；期待明确说明不足 |
| 研究探索 | 6 | 从证据形成可检验建议，按下一节独立评审 |

前 20 题在看模型回答前建立原文核查记录：预期答案要点、必要证据、准确定位、不可省略条件及常见误解。由未参与该次生成的评审者独立检查原文；生成器自评分或同一提示下的自我解释不能作为唯一判据。自动评估可辅助筛查，关键数字/条件和争议项必须回到原文裁决。

每题保存资料版本、问题、允许范围、所需证据、实际检索结果、最终 prompt 的证据清单、回答及引用、模型/配置和耗时。题目与运行记录的样例由本目录 `templates/` 提供；真实预期答案须后续核查填写。

### 5.1 指标必须拆开

- **关键证据召回**：固定检索预算，检查必要原文证据是否进入候选集合，并另记是否最终进入回答上下文。多证据比较题按证据单元计数，不能找到任意一篇便算整题成功。初始目标建议必要证据召回 ≥90%，同时列出逐题遗漏。
- **回答正确性**：在所需原文已取得并可用的标准模式下，前 20 题至少 18 题满足预先制定的答案要点。机制解释遗漏关键假设、比较不同设置却给绝对优劣，均不能只按文字流畅判对。
- **引用支持**：逐条核对“主张—引用”的关系。支持率初始目标 ≥95%；另报应有证据的实质论断中，获得有效引用支持的覆盖率，建议亦 ≥95%。无引用答案不得通过缩小分母获高分；存在来源编号只证明编号存在。
- **关键错误**：捏造论文/数据/定位、关键数字或结论成立条件错误、把导读当原文、把相关性当已证因果，任一项均阻断相应质量验收，不能被平均分抵消。
- **不足题**：4/4 均如实说明已知与缺口，不编造确定答案。允许解释现有材料并提出下一步查证，不要求空泛拒绝；对可回答题滥用“资料不足”仍计回答错误。

每题按模式预先填写`expectedBehavior`。分别测试纯导读、已有原文、允许联网等实际支持的模式：标准原文模式适用上述正确性/召回门槛；导读缺少必要证据时，通过行为是准确说明不足，不能要求模型猜出原文细节；联网模式另记实际获得材料，禁止用它的成功证明离线同样成功。在原问题旁加入无关论文，复测证据召回及回答；追加近义术语、重复版本或互相矛盾的材料，检查错误引用与版本混淆。

30 题是早期回归与问题发现工具。报告分子/分母、失败题和评审分歧；小样本通过不能外推为所有学科、千篇真实论文或所有模型都可靠。

## 6. 六道研究探索题的验收

逐题按“满足 / 需修改 / 不支持”评审下列维度，不给“创新性已证实”的二元自动分数，也不让 AI 替用户形成研究结论。

| 维度 | 可核查要求 |
|---|---|
| 依据与近邻研究 | 指出已读取的证据、相近研究和检索边界；现象与作者/系统推测分开；没有充分检索时明确新颖性未确认 |
| 可检验假设 | 写清改变什么、预期如何变化、适用条件和可能机制；不能只有“提升性能”“结合 A 与 B” |
| 最小实验 | 给出可执行的最小数据/任务、对照 baseline、指标、资源假设与操作步骤；若资源未知，给出待确定项 |
| 混杂与反证 | 说明预算、数据泄漏、实现差异等可能混杂；给出消融或控制方式，并说明什么结果会否定假设 |
| 结论边界 | 区分“值得试验”“已有证据支持”“尚未验证”；不把未检索到当文献空白，不承诺发表或必然创新 |

六题应同时包含：有充分依据的可执行改进、跨篇冲突待检验、已有相近工作的建议、资料明显不足的探索。有充分依据提出研究假设的题，须满足依据可追溯、假设可检验、下一步可执行。资料不足题按预设 `expectedBehavior` 核查缺口判断与查证计划，假设及实验维度可以说明理由后标为“不适用”，不必强行产出研究方向。发现编造来源、伪称创新或把预期写成实验结果，阻断探索功能的质量验收。

## 7. 交付报告与最终审阅

依照 [06-CODEX-FINAL-REVIEW.md](06-CODEX-FINAL-REVIEW.md) 交叉审阅，报告至少填写：实际起点/终点提交；完成的任务及范围变化；格式迁移与旧数据兼容；运行命令及真实结果；检查过的页面和来源定位；各规模性能表；30 题逐题结果与总分母；失败/未验证项；恢复演练与回滚方法。模板见本目录 `templates/`，不得用示例数字替代实测。

**阻断项**包括：已知数据损失或恢复失败、旧内容/笔记/会话引用被错误改绑、授权或计费 fallback 回归、无界加载/写入仍在关键路径、原文定位造假、关键学术事实错误，以及把模拟结果报告成真实结果。未满足性能门槛时不得宣称规模验收通过；只有明确记录的目标调整才能改变判定范围。

没有真实 API 使用授权或可用配置时，继续完成结构、迁移、模拟故障、原文核查和本地性能工作，将“真实模型质量、供应商稳定性”标为未验证。不要额外调用模型消耗额度，也不要以 mock 通过宣称整体完成。最终可以交付“工程部分完成、真实问答验收待执行”的诚实结果，并列出恢复验证所需条件。
