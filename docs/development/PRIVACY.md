# Minimal implementation context

## Research assistant extension

The reader can explicitly enable the current exploration as model context. Each submission then sends that topic's question, interpretation, unknowns, selected evidence, scope, constraints, candidates, deferred directions and decisions with a fixed version/hash. Consent is remembered per topic in session storage; only consent flags/IDs are stored there, not the research text. The reader may additionally select individual notes and saved documents from the current exploration, inspect their text/revision and withdraw selection. These attachments are off by default; changed or deleted records require a renewed selection rather than silently substituting new text. Both providers and API fallback use the same submitted snapshots. Other explorations, unselected notes/documents and receipts are excluded. Topic history can include previously sent questions and answers; withdrawing a current attachment does not erase prior conversation records. Exported research/task files contain deliberately downloaded personal research context; they are private handoff files, never public content packages.

The backend stores historical snapshots, not a second authoritative research state. Complete answers may propose changes; only explicit adoption writes to IndexedDB. Source excerpts retain model/guide/original/web provenance. Deleting an AI conversation does not erase source excerpts deliberately retained in research documents or decisions. Provider credentials remain backend-only and are not included in any research backup or handoff.

The permitted audience description is a computer-science graduate reader with some prior paper-reading experience who wants survey guidance, paper assistance and research exploration. Agent applications are the initial content area. These functional facts are sufficient; do not ask for or infer a more specific biography.

No requester/operator name, institution, city, country, nationality, age, contact details, account handles, device identifiers, private hypothesis, personal reading history, original machine path or old repository identity belongs in the project. Do not add sample identity fields, analytics, personal screenshots or environment inventories. Tests use clearly synthetic text and records, never a copy of the operator's real notes.

Public scholarly authors, paper titles, source institutions and necessary citations are bibliographic evidence and must retain accurate attribution. The language of a guide and its research subject are not grounds for inferring the operator's identity. Privacy removal must not fabricate affiliations or alter academic facts.

The developer works only from this standalone input. Do not inspect parent/home folders, other projects, global memories, account configuration or shell history to fill gaps. Do not read sensitive originals first and attempt to sanitize them afterward. Do not include absolute machine paths in output artifacts or copied reading context; use project-relative artifact paths and relative application routes.

The original reading, notes, exploration and context-copy features send no private data to a model or service. The optional AI reading extension sends the explicitly submitted question, selected passage, reviewed guide context and bounded history from that AI conversation to the configured model. Enabling web search additionally permits the model's search query to be sent to Tavily. Notes, exploration records and reading history are not automatically included. The panel discloses this before sending; see AI-READING.md for the exact boundary.

AI conversations and source snapshots are stored by the local backend, separately from browser IndexedDB. Browsers connected to that same service share these AI conversations; this is a single-user local service, not account isolation. AI export/import/delete controls operate on that store only. Copy/export actions have an exact preview or a clear local-download action; reading an external source is deliberate. Credentials and personal records remain outside source packages and Git. No Git identity setup, commit, push or publication is authorized by this handoff.

Optional official ChatGPT authorization stores only the protocol-required identifiers and credentials in ignored backend-private storage. Windows credentials use DPAPI encryption for the current OS user; other platforms currently use owner-only files. Access/refresh tokens never reach the frontend, AI backups or logs. The UI uses generic connection states without account identity. Authorization and refresh contact official OpenAI endpoints; local tests use synthetic credentials. Provider login neither reads other programs' account files nor changes the browser-record schema. Provider selection is explicit. The reader-requested quota fallback is enabled by default and can be disabled in ChatGPT settings: only a structured subscription/application usage-limit error allows the submitted question, bounded history, guide context and gathered sources to be sent once to the configured API, which may incur separate charges. Network/authentication errors and ordinary rate limits do not switch providers. The actual provider/model and any unfinished subscription fragment remain in the local turn and its AI backup; opaque reasoning is never transferred.

The reader may enter API configuration in **AI 设置**. The password field is sent only to the local backend on Save, cleared after confirmed saving, and never persisted in browser storage. The ignored `server/config.local.json` file remains the credential store; settings reads return only whether a key exists. Changing a service address requires re-entering its key so a stored key is not silently sent to a different provider. Configuration is excluded from conversation backups.

An explicit ChatGPT availability check sends a fixed short prompt using this application's own authorized connection. It sends no guide text, questions, notes or history, does not call tools, and may use a small amount of subscription allowance. The response is discarded; no conversation or usage record is created. Only the last confirmed availability state, time, model and sanitized failure notice are held in backend memory. Opening settings and refreshing status do not start inference checks. A normal ChatGPT answer also updates this observation; API fallback success is not reported as ChatGPT recovery.

For deliberate backend requests, the network adapter can consult Windows' system proxy resolver for the destination URL or use explicitly inherited proxy environment variables. This does not inspect proxy applications' files, accounts or credentials. Proxy addresses are used only in memory and are not logged, returned to the page or included in backups. The adapter does not modify system proxy settings or perform connectivity probes at startup. The resolver helper receives only the destination URL, without request headers, keys, tokens or question bodies.

These instructions govern the project; they cannot prevent a host from automatically attaching account or machine context before the developer reads them. Host configuration and filesystem isolation must be arranged by the operator separately. A file audit is not a guarantee about account behavior or automatic context.
