# 探索通过 Git 跨电脑传递

## 保存边界

原实现将探索唯一保存在当前浏览器、当前地址的 IndexedDB 中，Git 只传递代码和公开文献。AI 后端保存的研究快照只是历史提问材料，不能替代最新工作稿。这次扩展明确增加项目文件持久化：完整探索写入 `research-workspace/explorations/`，由用户的私人 Git 仓库传递。

记录保留原 ID、问题、状态、出处、证据、研究工作稿及其历史、文献关联、交付凭据、决定和选文文件。不会从标题或截图重建虚假的个人数据，也不通过扫描浏览器配置获取数据。第一次运行新版网页时由原浏览器主动迁出；另一台电脑启动后从项目载入。

此次授权仅覆盖探索。其他个人笔记、阅读标记和位置、AI 问答、原文文件及密钥维持各自已有备份边界。探索中已经保存的摘录本身会传递，相关笔记 ID 不意味着读取或上传该笔记正文。

## 双向更新与冲突

每条探索的每次项目写入生成独立、不可变 JSON 修订，父修订组成有向无环图。内容 hash 用作文件名；并行电脑对同一父版本的改动生成两个文件，Git 的文件级合并不会让一个覆盖另一个。服务读取所有修订并计算当前头部；存在分叉时网页保留本机与项目候选，供读者明确选择。

浏览器另存同步基线。只有本机改变就向项目追加，只有项目改变就原子载入；双方同时改变时进入冲突。首次双方同 ID 不同内容也需要选择，不使用 `updatedAt` 或 `recordRevision` 比较不同电脑的新旧。载入后保持本地修订检查有效，已打开编辑器的旧草稿不能覆盖新内容。请求发送中本机再有变化时，保留并在后续轮次处理。

删除通过追加 tombstone 传递；旧电脑回来不会复活旧记录。项目曾有修订、后来整个文件组消失时，客户端报告项目历史缺失，不能把它视作新建项目而重发旧内容。手动选择解决冲突后追加一个包含当前各头部的修订，原内容仍可回查。

本地服务尚未连接、文件只读、格式/摘要损坏、父修订缺失或空间不足时，已有浏览器记录继续可用；页面明确显示未写入项目，可重试。原有个人备份仍可使用。

当前工作区最多128 MiB、20000个修订文件；每个修订保留完整探索（含工作稿历史），频繁编辑长工作稿会增加磁盘与Git体积，可能先触及此上限。达到容量时明确报错，不丢弃历史或假装已同步。

## 本地 API 与隔离

`GET /api/workspace/status` 提供本机会话 token。`GET/POST /api/workspace/explorations` 使用与本地 AI 相同的主机、来源和 token 检查，但不依赖模型配置或启动推理。接口只接受固定协议、UUID、hash 和严格探索结构，不接受任意文件路径；读写都限定工作区，拒绝符号链接和不完整历史。写入以当前所有头部作比较，过时请求返回冲突。新文件完整写入后才发布为可读取修订。

项目数据目录不由 Vite 静态资源服务暴露，也不进入生产 bundle。隔离测试来源4174对 workspace 和 AI 接口均拒绝连接真实服务；浏览器测试使用模拟服务或独立合成数据目录。后端响应不输出机器路径、凭据或记录正文到日志。

## 日常操作

“已保存到项目”不等于远程已同步；仍需 Git 提交/推送，另一台再拉取。操作步骤见[工作区说明](../../research-workspace/README.md)。不要在运行中的项目目录切换到不含所需历史的旧分支；如需检查旧代码，使用独立检出目录。

清除浏览器记录会清除同步基线并暂停同步；点击恢复才重新载入项目。普通方向删除通过 tombstone 传递。Git 中的历史修订不会随页面删除而彻底擦除。
