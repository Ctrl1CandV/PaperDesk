# 研究助手扩展

后续工作的最新需求见[问题到方向与选文文件的交接](RESEARCH-ASSISTANT-HANDOFF.md)。本文件描述已实现的第一版及原有阶段安排，不表示“通过自然讨论形成选文条件和研究主线”的新体验已经完成。

本扩展沿用产品规格 1.1 和现有本地架构。当前交付终点是：理解已取得的论文与综述，使用读者授权的笔记和探索，在同一研究主题的多个会话中持续讨论，并依据读者想法与授权形成可交接的实施文件。具体检索、内容制作、开发或实验由外部 Harness 使用其自身技能与插件执行，不属于本助手的完成门槛。研究探索是唯一的当前研究状态；采纳假设不等于证实假设。

## 三个阶段

本次交付第一阶段的可用版本，并接通基本文档出口；不将三个阶段全部完成作为本次要求。后两阶段根据实际阅读使用中的问题继续完善。

1. 持续研究：在阅读 AI 面板选择关联探索，或在探索详情打开研究对话。明确启用该主题的研究上下文后，问题携带研究版本、范围、约束、候选、暂缓、决定和证据快照。同一主题可跨论文或无论文继续，模型切换不改变提交的快照。完整回答中的受限提案可预览、采纳；并发编辑使旧提案失效。
2. 研究判断与文档：沿用有预算的来源工具，按问题比较条件、反证和材料缺口。可将完整回答保存为研究文档，再编辑为证据综合、方向比较、阅读计划、实验方案或阶段计划。文档保留来源问答和摘录，删除原会话后这些摘录仍保留。研究质量不能由结构校验或提示词保证。
3. 实施文件交接：从研究讨论与保存的文档准备执行任务，说明目标、既有判断与理由、公开来源、具体工作、交付物、验收、停止条件与授权范围，预览后保存固定版本，下载同源的 `brief.md`、`brief.json`。终点是执行者仅凭文件即可理解已确定的意图；无需实际执行完整任务来验收助手。已有回执入口保留为可选功能，后续工作不以扩展回流或自动执行为重点。

## 操作边界

- 普通论文问答保持原入口，不必建立探索。研究上下文许可按主题在当前浏览器会话保留；不会自动加入其他探索。回执不会在普通问题中整库发送。
- 研究对话可明确选择笔记与当前探索的已保存文档。默认不选，选入前可预览正文和修订；已选内容发生修改或删除时须更新选择。实际发送的资料固定为该轮快照，与研究状态快照分别保存。`relatedNoteId` 不会自动授权笔记正文；个人记录不作为论文事实。
- 编辑过的计划需要选入相应文档修订后再讨论。同主题历史提供最近讨论提示、关键词搜索和逐轮补读，旧模型回答仍只是讨论记录。当前研究状态优先，跨主题历史不开放；不保证语义相近的改述都能召回。探索证据仍按时间和预算选取，未纳入项可见，第一版不增加向量服务或自动研究代理。
- 提案总是需要界面的明确采纳。自然语言中的“记下来”目前产生提案，不自动写回；回答不得声称已经保存。中断回答不能采纳或保存为完整研究文档。
- 当前不维护自动生成的长期摘要。当前状态每轮带入，旧讨论由近期问答提示和主题内历史工具补充；没有摘要覆盖新状态的问题。没有已选会话时，可明确继续最近对话。
- 文档草稿明确保存后可刷新继续；未保存的输入有离开提醒和下载副本。当前任务编辑器创建一个稳定 ID 的执行任务，可在交付物中列步骤；底层协议支持带依赖的多任务，尚无多任务编辑器。
- 保存任务后编辑文档只影响草稿；再次确定形成新版本。重复同内容回执不产生变化，冲突回执不覆盖已有记录，并可下载保留来件。迟到结果仍属于原版本。
- 回执是执行者报告，不是应用独立核验。内容包准备、校验、导入、用户已读及研究结论分别记录。网页不会执行代码、自动出版内容或运行 Harness。
- 回执继续讨论目前使用可见问题文本，最多 6000 字。超过时明确提示选择本轮相关结果，不静默截断完整回执。

## 实施与验收

探索页的“让助手整理实施文件”准备一个可检查的问题，读者发送后才调用模型。完整回答保存为研究文档，可修改并直接下载 Markdown；无需重新填一套任务表格才取得文件。选中文档也可准备后续问题，仍须在助手内主动选入正文。固定任务版本和回执收在可选功能内。

协议见 [研究契约](RESEARCH-CONTRACTS.md)，本次必要检查见 [第一版检查](RESEARCH-ACCEPTANCE.md)。优先完成主流程和保存安全；真实回答质量在主动使用时持续观察。工程检查通过不等于已经完成真实模型验证，也不需要启动外部 Harness 才能交付这一版。
