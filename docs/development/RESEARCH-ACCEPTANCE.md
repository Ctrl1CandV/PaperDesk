# 研究助手第一版检查

三阶段计划继续保留。本次先交付可用的第一版，优先实现材料理解、授权记录、连续讨论和实施文档，不以大规模模型评测或完整 Harness 实战作为完成门槛。外部执行者的技能、插件、开发、实验和结果回流由其自身工作流负责。

## 本次必要检查

```text
npm test
npm run build -- --logLevel warn
npm run test:e2e -- tests/e2e/research-discussion.spec.ts tests/e2e/research-records.spec.ts tests/e2e/research-assistant.spec.ts tests/e2e/research-workspace.spec.ts tests/e2e/exploration.spec.ts --reporter=line
```

Node 检查覆盖共享协议、主题隔离、版本冲突、备份与模型请求；构建覆盖内容和类型。浏览器只针对本次研究流程检查，不重复运行无关页面的完整测试集。测试使用明确标记的合成记录和模拟模型，不读取真实私人笔记。

| 主流程 | 最低要求 |
|---|---|
| 授权资料 | 笔记和文档默认不发送；可预览、选择、撤销；请求与回放保留实际修订。已选资料变化不能悄悄替换。 |
| 持续讨论 | 同主题可恢复旧会话、读取相关历史；换论文或模型不串主题，不以旧回答覆盖当前决定。 |
| 研究记录 | 完整回答可保存，提案经明确采纳后写入；旧版本、重复提交和并发修改不覆盖新状态。 |
| 实施文件 | 从讨论整理并保存文档，下载包含正文、来源和缺口的文件；生成请求不自动发送、不虚构执行授权。 |
| 对话指令 | `/方向` 在未关联时建立方向并带入起点节选、之后的讨论归入它，已关联时直接写入更新并保留审计；`/选文` 按目的保存为新文件，推进类必须有方向，信息不足时不保存；阅读标记只随 `/选文` 发送。 |
| 探索页 | 方向行显示阶段、最近一条阶段记录与积累数量；方向页以研究工作稿为主体，侧栏给出阶段与下一步、阶段记录与“记一笔”、相关文献和选文文件；“继续讨论”打开同一对话；工作稿可导出为项目起始文件。 |

检查实际请求和保存内容，而不只检查按钮存在。发生相关失败时修复并复跑对应场景；无需为低影响文案或布局另建测试。检查桌面与模拟窄视口，说明所用视口，不把截图当作真机验收。

## 使用中的质量观察

真实模型质量在主动使用时继续观察：选一个公开主题，经过几轮讨论、新建一次同主题会话、修改一个决定，最后整理一份实施文件。重点核对材料是否理解正确、旧决定是否接上、文件是否忠于讨论和授权。真实调用应使用读者主动配置的服务；没有调用时如实说明，模拟响应不能证明回答质量。

不要求两套长情境、固定轮数、独立评分模型或专门的 Harness 演练。拿到文件后能看清目标、已有依据、下一步、交付物、完成与停止条件即可；尚未决定的事项明确保留，不靠猜测补齐。后续实际使用暴露的问题再转成有针对性的回归。

伪造来源、越过授权发送笔记、混淆主题或修订、无声覆盖决定属于必须修复的问题。当前未做的真实模型检查和外部执行不应写成已通过，也不作为这一版工程交付的额外门槛。实际命令、结果及未验证行为见 [项目状态](PROJECT-STATE.md)。
