## 2. 产品真正要解决的问题

PaperDesk 已有比较完整的论文和综述阅读内容。助手的目标是参与阅读后的思考，帮助确定下一步读什么、为什么读，以及哪些问题值得沿着一条研究主线继续追踪。

读者往往只能提出局部问题、疑惑、感兴趣的现象或粗略想法，还不能给出明确研究方向。形成方向本身就是助手应参与完成的工作。进入持续讨论不应以读者已经完成研究归纳、填写目标和规划字段为前提。

期望的循环是：

1. 阅读综述，了解领域的一部分内容与关系。
2. 根据想继续了解的部分，让外部 Harness 加入相关论文。
3. 阅读多篇论文，产生问题、笔记、比较和初步判断。
4. 与 AI 答疑并持续讨论，逐步澄清兴趣、证据、分歧与未知。
5. 从讨论中得到感兴趣、值得进一步调查的方向。
6. AI 协助判断研究方向和主线，提出合理的建议与下一步。
7. 将已经讨论清楚的内容整理成文件。
8. 外部 Harness 依据文件追加论文或综述，进入下一轮阅读和讨论。

这条循环可能反复缩小、调整或暂缓方向。当前问题可以先被保留，尚未形成方向是正常状态；候选方向、选定方向和经过证据验证的结论也应保持区别。

## 3. 助手的两类主要成果

以下是对文件信息质量的要求，不是本轮确定的新 schema、按钮名称、页面布局或固定模板。文件可以按实际需要独立生成、更新或相互关联；不应强迫每次普通答疑都生成两份文件。

### A. 下一轮阅读与文献筛选文件

核心作用：把“接下来需要理解什么”交给具有检索、审阅和内容生产能力的 Harness，使其不必重新询问已经讨论过的意图。

应能表达：

- 本轮要解决的阅读问题、为何现在继续这个问题、与已有阅读的关系。
- 需要的是领域综述、机制论文、方法比较、评测、失败案例或其他类型的材料，以及相应目的。
- 关注的具体方向、概念、条件和范围；有依据时整理可用于检索的关键词及同义表达。
- 纳入与排除条件、优先级及其理由；避免只给出宽泛领域名称。
- 已有材料覆盖了什么、还缺什么、哪些内容不必重复，以及可能有用的比较对象或反例。
- 已知论文或来源的可核对身份与版本；没有检索核实时，不虚构具体候选论文或宣称完成了全文筛选。
- Harness 应返回的成果，例如候选列表及取舍理由、建议阅读顺序、来源与缺口，或在授权范围内准备适合入库的导读/综述。
- 已明确的数量、时间、资源、来源要求和行动权限；未讨论的事项保留为待确认，不擅自补成授权。
- 满足什么条件即可结束本轮选文，什么发现需要返回讨论。

重点是方向与筛选标准的明确性。外部执行者可以根据自己的技能和插件选择检索与制作方法，平台无需代替它完成全部执行。

### B. 研究方向与研究主线文件

核心作用：把讨论中逐步形成的研究兴趣和判断沉淀下来，使后续会话、阅读和外部工作围绕同一问题继续。

应能表达：

- 起点是什么问题，问题为什么值得继续调查。
- 从多篇论文、综述、授权笔记和讨论中形成了哪些认识，依据和条件是什么。
- 候选方向有哪些，它们的关系、区别、支持依据、主要疑点与可行性约束是什么。
- 当前倾向哪个方向、为什么；哪些暂缓或放弃，理由是什么。
- 研究主线中的核心问题、子问题及相互关系；如果方向仍不稳定，应明确尚未收敛。
- 哪些内容属于文献事实、读者观点、助手推断或待验证假设。
- 下一步先补什么理解、阅读哪些类型的材料、比较或检查什么，以及什么证据会改变当前判断。
- 哪些判断已经由读者确认，哪些仍是建议；后续修订不应无声覆盖原有决定及其理由。

研究主线不是一个未经讨论就固定的论文题目，也不是新颖性、可发表性或研究成功的保证。最小实验或开发建议可以在问题需要时出现，但它们不是每轮讨论的必填内容。

## 4. 读者如何参与，助手应承担什么

读者负责表达问题、兴趣、已有想法和真实限制，指出误解，并对重要方向和行动作出选择。清晰的指令应能推进整理与保存，不应要求读者在另一个 Harness 再讲一遍同样的背景。

助手应根据实际可用材料，承担解释、追问、比较、归纳、整理候选方向、提炼筛选条件和形成文件的工作。必要澄清应围绕会实质影响判断的缺口，不能把整个研究表单换成一连串必须回答的问题。

上下文需连接当前论文/综述、明确授权的笔记、当前问题及研究状态、相关旧讨论和选入的文档修订。换论文、换会话或重新打开页面后，已经确定的目标和理由不应完全依赖读者重述。

普通概念答疑仍然直接回答；在读者表达继续研究的兴趣、比较方向或要求整理时，助手再参与这类沉淀。保存、状态变化和外部动作的边界仍需清楚；不能把一次阅读、一个回答或一个草案当成已读全文、已掌握或已证实。

## 5. “探索”界面的反馈及必须保留的区别

读者认可探索页面本身，认为集中查看和维护问题、依据、判断与后续安排有价值。问题集中在概念和进入路径，尤其是阅读页“加入探索”时的负担；这不是要求直接删除探索页面或已有记录。

所提供截图的可复述内容如下，不需要原始图片即可理解：

- 弹窗标题为“加入探索”，先选择保存到已有探索或创建新探索。
- 创建时展示探索标题、继续追问的问题、当前状态。
- 还展示“补充解释与未知”“研究范围、约束与候选方向”“记录一项研究决定或修订”等折叠区域。
- 随后有“下一步”行动类型，以及随记录保留的材料和批注。
- 页面较长，需要滚动，整体像在维护一份研究档案。

事实边界：当前代码并非把所有字段设为必填；主要必填项是标题与问题，部分字段已折叠。这仍不能解决用户指出的负担：初始交互提前呈现了一套研究规划体系，而许多内容恰恰尚待讨论形成。

应特别关注的责任错位：当前解释、未知、候选方向、暂缓原因、研究决定的理由和建议下一步，很多都应由助手从讨论中整理后供读者修订或确认，而不是要求读者先主动写好。真实资源限制、个人兴趣或意愿不能由模型编造。

保留结构化数据并不等于必须让初次使用者填写全部结构。后续具体如何处理问题与探索的关系、创建入口、会话承接、整理与确认，需要下一轮设计和实施；本轮未指定方案。

## 7. 已确认的主要缺口

1. **问题到探索的路径倒置。** 开始持久研究讨论通常先要手动创建探索；已有探索是上下文与工具的前提，而不是讨论自然形成的成果。
2. **普通论文会话与研究主题的衔接不足。** 当前能关联已有探索，但没有从正在进行的普通讨论创建研究记录并承接相关内容的流程。
3. **表单承担了过多归纳责任。** 初始加入材料和后续完整维护共用 `ExplorationEditor`，读者过早看到大量研究字段。
4. **两类核心文件缺少明确的产品语义。** 现有入口泛称“研究文档”“实施文件”；保存全文回答和通用提示词不足以保证阅读筛选条件或研究主线完整。
5. **AI 形成下一步与既有下一步数据没有完全接通。** `RESEARCH_FIELDS` 不含 `title`、`nextAction`。AI 能追加 `next-step` 类型决定，但这与探索的结构化 `nextAction` 不是同一个写入路径。
6. **本库下一步阅读与持续讨论仍分离。** 现有本地匹配有用，但不能把它当作已实现多轮讨论驱动的筛选规划。
7. **连续性存在实际边界。** 近期摘录很短，旧历史仍按词法检索，探索证据按时间和预算纳入；不能用存储成功证明语义记忆可靠。
8. **真实研究效果未被工程测试证明。** 已验证版本、隔离、保存和导出等行为；尚未证明助手能稳定把模糊问题推进为有用的研究方向与选文条件。

这些缺口应成为后续工作的依据，而不是继续扩张执行回执、自动实验或更多手工字段。

## 9. 通过 Git 交接任务

接手者更新 main 后，从本文和 START-HERE.md 开始即可理解任务。本次交接包括此前研究助手实现、远程配色更新、最新需求、已知缺口、代码入口和实际验证记录；无需原始聊天、截图或单独复制本机缓存。

源码、共享契约、类型声明、测试、package-lock.json、schemas、审核后的阅读内容和内容生产工作流均纳入仓库。当前内容包括 14 篇材料、21 个保留导读修订。src/research/workflow-refs.json 及其四个引用文件均已纳入，当前摘要匹配；静态核对未发现源码相对 import 的缺失或大小写不一致。

少量本地数据不随 Git 同步：

| 类别 | 交接边界 |
|---|---|
| 笔记、探索、文档、阅读状态 | 浏览器 IndexedDB 数据；开发可用合成记录，不需要索取真实私人记录 |
| AI 会话、导入的原文及核验材料 | private/ 内的本地数据；导读仍随仓库提供，原文全文库不会随之出现 |
| 模型配置与登录凭据 | 目标环境自行配置，不进入源码或交接正文 |
| 依赖、构建产物、测试缓存和截图 | 重新安装或生成；本文已记录关键需求和检查结果，不依赖这些缓存 |

这些数据不影响理解和接手本任务；实际需要恢复时再参照 OPERATIONS.md 的独立备份流程。不要把私人导出文件加入提交。内容导入恢复收据等忽略文件不随 Git 同步，也不意味着可以随意删除。

## 10. 接手后的基本运行

使用 package.json 支持的 Node 版本（^22.13.0 || >=24.0.0），在项目根目录按需运行：

```text
git pull --ff-only
npm ci
npm run build
npm start -- --no-open
```

以上拉取命令适用于没有本地分歧的 main；已有本地改动时先检查并保留，不应强行覆盖。访问 http://127.0.0.1:4173/library；开发用 npm run dev。运行与模型配置细节见 OPERATIONS.md，不需要为开始开发先迁入真实记录。

不要复制其他环境的 node_modules 或改动审核内容字节。普通源码按 .gitattributes 使用 LF，content/** 保留原始字节；相关工作流文件变动时需同步更新引用摘要。模型未配置不妨碍阅读平台启动，真实模型和特定运行环境是否可用以实际验证为准。

## 11. 后续实施与检查的约束

- 以可用体验和上述两类成果为中心，不继续扩大为执行 Harness、自动实验或插件安装平台。
- 保留探索页面的价值和已有记录；改动创建/整理链路时维持版本、证据归属、备份和冲突保护。
