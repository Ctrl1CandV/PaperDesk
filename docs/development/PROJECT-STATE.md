## 界面整理、组会汇报页与快捷提问 · 2026-11-14

这一天先做了一轮整理，读者看过后认为只是小优化，并允许较大的改造，于是又做了一轮结构调整。审核正文没有改写。

**书架按阅读集合组织。** 书架分成公共阅读集合里的三组（Agent 与大模型基础、多智能体通信、Agent 与模型评价，见[阅读集合](../content/RESEARCH-READING-SET.md)）：每组一块，写明阅读路线、篇数和“导读已读 n / m”（只来自读者自己的导读标记），组内按阅读次序排成对齐的行——序号、标题与副标题、读完能做什么、类型与出处、阅读标记和“有汇报稿”。打开信息卡后左侧收成紧凑导航。目录排序本来就与三组一致，所以书架顺序和键盘顺序不变。全站字号收成十档，最小 12px。

**阅读页的阅读条。** 工具行固定在正文栏顶部，始终显示当前章节序号与名称，下方一条细线显示读到全文的哪里；目录标题显示“06 / 13”，读过的章节变成已读样式。原论文链接移到文章标签行。

**组会汇报改为“讲一张导图”。** 不再做成幻灯片。参考了 markmap（两侧展开的导图，分支线上直接写标签，段落和表格不放进导图）和 Kumu 的演示方式（同一张地图逐步聚焦、放大，旁边配文字）。汇报页 `/present/:guideId/:revision` 顶部是一句话主张和整张导图，下面按分支排出每个讲解点的网页内容：一句要记住的话、原图、关键词说明或表格、出处、讲稿提示，以及打开完整导读章节的“导读原文”；宽屏时旁边的导图跟着阅读位置框住当前分支。“开始讲述”时开场只画主干，每进入一个部分就框住这条分支，每讲一点就点亮它并展开关键词，最后回到全图回顾再收束；`O` 看全图，`N` 开讲稿提示，底部有按计划时间分段的进度和计时。汇报稿改为“开场—若干部分的讲解点—收束”的结构，只能使用该导读修订已有的章节、原图和出处，由 `server/content/presentations.mjs` 检查。首份是 2025 年通信综述（导读修订 2）：4 个部分、13 个讲解点、15 分钟，用到导读的全部 5 张原图。写法见[汇报稿](../content/workflows/PRESENTATION.md)。

**AI 答疑的快捷入口与上下文。** 正文里用鼠标选中一段，旁边出现“解释这段 / 问 AI / 记笔记”；“解释这段”会打开面板并带着这段文字直接发送。输入框上方有一行一键问题（针对选中内容或当前一节），外加只填入输入框的“有个想法”。阅读工具里增加“问 AI”。后端首轮改为尽量发送提问所在的完整章节（原先固定在约 5000 字节），并把新配置的默认 `contextTokenLimit` 提高到 65536；系统提示补充了“先给结论”“对读者的想法给判断、漏洞和下一步”“已有内容不重复检索”，同时压缩了其他句子，总长度不变。详见 [AI 阅读](AI-READING.md)。

实际检查（结构调整之后）：`npm run build` 通过；`npm test` 585 项通过、0 失败；浏览器测试全量 231/231 通过，最后几处小改动后又复跑了汇报页、书架和阅读页相关的 25 项，全部通过。本机项目浏览器缓存为空，浏览器测试通过 `.cache/design/pw.config.ts` 改用已安装的 Chrome 运行。汇报页测试覆盖：导图标签实际字号不小于 13px、点导图跳到对应内容、讲述时逐步展开、20 步内容在 1440×900 下都不溢出、手机为提纲且无横向滚动。查看了 1440px、1024px 与 390px 模拟视口下书架、信息卡、阅读页（顶部与滚动中）、汇报页（顶部导图、跟随导图、讲述的开场、部分、讲解点、回顾与收束）以及深色主题的截图；页面检查脚本在书架和阅读页没有剩余问题，汇报页剩下的提示是导图内部的字号层级。

未验证与限制：

- 没有提交、推送或部署。
