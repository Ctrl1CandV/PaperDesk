# 交给 Codex 的实施任务

以下内容可作为完整任务直接交给在 PaperDesk 工作区运行的 Codex。

## 任务与已确定边界

你正在 PaperDesk 项目内实施本轮改进。请落实代码、必要内容样板和验证，持续推进至本轮完成，不能只提交规划或泛化建议。按照 [03](03-AI-DATA-IMPLEMENTATION.md) 实现数据与问答，按照 [01](../../content/workflows/CONTENT-WORKFLOW.md)、[02](../../content/workflows/SOURCES-AND-VISUALS.md) 固化内容流程，按 [05](05-ACCEPTANCE.md) 判断完成。

用户已经认可当前前端和内容展示。保留书架、导读卡、深读布局、完整段落和现有阅读宽度；只做本轮任务需要的来源入口、材料状态与问答交互改进。不得改造、安装或集成 `grad-companion-plugin`，也不得去其仓库寻找私人阅读记录。

不新增云部署、网站账号、跨设备同步或后台自主文献生产。已有 ChatGPT/API 接入、可选联网、幂等、取消、预算和记录保护继续保留。不要以解决扩容为由删掉所有限制、验证、测试或旧版数据。

## 开始前

1. 阅读 `AGENTS.md`、`START-HERE.md`、`PROJECT-STATE.md`，以及其中要求的 PRODUCT、IMPLEMENTATION、EXPLORATION、PRIVACY、MAINTENANCE、GIT-POLICY 文档。再读本目录 00–05 和现有 CONTENT、CONTENT-UPDATES、AI-READING、OPERATIONS。
2. 检查当前提交与工作区改动，以实际代码为准。参考基准为 `1668527a9e84cacac85019c569f44719bb90252d`，不要 checkout/reset 到它，不覆盖用户未提交改动。记录现状差异和已完成能力。
3. 运行必要的基线内容校验、类型检查与相关测试，区分既有失败与本轮问题。环境不足时先把具体缺项写清；使用项目规定的 Node 与项目局部依赖，不修改全局配置。
4. 在 `.cache/` 中保存合成数据库、临时原文审阅材料和详细测试日志；只把不含私人信息的简明证据与报告纳入文档。不得为测试读取用户真实笔记、会话、密钥或其他程序账号文件。

## 实施阶段与检查点

| 阶段 | 工作内容 | 完成检查点 |
|---|---|---|
| P0 基线与设计 | 核对代码，列出真实改动点、数据迁移和依赖选择 | 简短方案与基线结果齐全，已有功能不被重复开发 |
| P1 存储和恢复 | AI/个人记录增量容量统计；数据库查询索引、分页；运行容量与备份分离；兼容迁移 | 合成旧库与旧备份可迁移恢复，超过旧 16 MiB 后仍可正常提问，高频写不扫描全库 |
| P2 按需读取 | 轻量书架清单、异步正文/旧版本读取、有界缓存、索引代次管理 | 首屏不加载全库正文；切换、回跳、旧版笔记和并发响应正常 |
| P3 原文证据 | 固定材料保存、HTML/文本层PDF解析、准确定位、证据伴随数据、持久化检索 | 三篇样板原文可用、缺口明确、精准入口可打开，资料更新不混用版本 |
| P4 问答与探索 | 原文工具、两个provider链路、来源标识、上下文预算、解释与研究建议、历史回放 | 具体问题能回原文；研究建议有证据与可检验实验；旧来源与备份可用 |
| P5 内容样板 | 按01/02补必要定位、教学图或专题深读，并发布新修订 | 三篇样板通过独立内容检查；旧正文、引用、笔记和阅读状态保留 |

每阶段完成后用一段简洁更新说明成果、验证和剩余事项，然后继续下一阶段。常规可逆实施选择自主决定；没有真实阻碍时，不在每个阶段重复请求确认。若会话中断，把当前阶段、改动路径、已跑命令和下一步留在工作区，恢复时接续，不重做已验证工作。

## 主要代码落点与联动要求

### P1：不能只改一个容量常量

检查 `server/store.mjs`、`server/http.mjs`、`server/validation.mjs`、`src/assistant/api.ts`、`src/records/store.ts`、`src/records/validation.ts` 及备份界面。迁移把计数字段、查询字段和索引一起设计，事务内维护字节差额；正常流式保存不能再调用全库 snapshot。保留导入冲突处理、running恢复、请求幂等和fallback快照。

浏览器续读/笔记记录也应避免每次更新读取所有 object stores。个人记录格式若改变，显式升级与迁移；不要暗中把原有个人数据迁入AI后端。新版备份需完整恢复、可取消/失败回滚，并继续读取旧版；大备份不能靠一次无界 JSON.parse 或巨型响应全量留在内存。

### P2：异步内容仓库要改完调用方

检查 `src/content/repository.ts` 及 Library、Reader、navigation、笔记、探索和关联链接调用方。使用小型目录索引保持书架流畅，正文按选择加载。增加取消/迟到响应保护，缓存有边界；不要通过库内 list/resolveRelated 间接加载所有正文。阅读页在AI后端不可用时仍可显示已打包的审核内容。

后端内容/检索模块从启动时全量解析改为可复用索引与按需读取。目录提交成功后触发增量索引，重试与恢复要幂等。索引可重建，原始材料与历史回答证据不可随意清理。

### P3：材料、解析、核验是不同状态

依照02实现材料与来源单元的独立schema、处理状态和稳定关系。至少支持明确导入固定版本HTML与有文本层PDF。依赖优先项目内、可复现并可替换；查验当前库版本与解析能力，不编造API或默认宣布图表公式完整。

词项检索起步必须验证中英混合、中文短词、缩写、模型/数据集名和条件查询。若真实题集发现显著语义漏检，再加入必要的查询改写、语义召回或重排，并用相同题集比较收益与成本。结果必须提供实际来源定位和读取范围。

### P4：新来源类型必须贯穿全链路

`original`来源和新工具参数需要同时覆盖 API provider、ChatGPT provider、runtime、HTTP、validation、来源卡、历史记录和备份，不允许只接通一种provider或把原文假装成网页。旧回答的编号和来源文本必须仍能正确回放。

实现阅读解释和研究探索两类行为。探索至少给出可追溯的已有证据、明确的待验证假设、最小实验、baseline/metric/控制变量与反证，不能依据“没有搜到”宣称创新。补充解释与论文结论保持归属，有限材料可以支持问题梳理，不能支持虚构的结果。

模型配置、搜索和外部请求延续用户已明确启用的路径；不读取其他应用的凭据。没有已获许可的真实模型条件时完成工程与离线验证，把真实问答验收保留为未验证，不冒充整体通过。不要为省事通过任意URL抓取、自动开启联网或默认发送个人笔记来获取证据。

### P5：样板落实到内容，避免只写抽象能力

使用现有 `agent-memory-survey`、`streamingllm`、`rag`。每篇形成原文材料记录、必要图表核查、关键主张映射、可用定位和问答示例。补图与专题按真实理解难点决定，图注-only和解析失败明确保留。

修改正文、定位元数据或资产时按现合同发布新revision；旧修订保持原字节和原身份。正文结构没变时保持既有unit的语义；不要为排版整齐重编号。卡片`library-briefs.json`逐篇审阅并绑定新revision，遵守当前导入器不接受该文件的边界。不得批量重写全部14篇或为了对齐新模板稀释已审核内容。

## 验证与报告

实施中优先跑与改动相关的有意义测试。完成时至少执行现有 `npm run validate:content`、`npm test`、`npm run typecheck`、`npm run build`，以及覆盖本轮受影响阅读/来源/笔记/备份/AI链路的浏览器测试。若项目门槛要求全套E2E，按门槛执行；修复后按风险复测，避免无目的重复全量运行。

按05分别记录工程、内容/定位、性能、真实问答与探索质量。新增检索来源、迁移和备份不能只写镜像实现的单元测试，必须覆盖失败恢复和旧数据。真实题集不得使用生成器自评作为唯一裁决。

使用 `templates/acceptance-report.template.md`，生成 `docs/evidence/reading-ai-upgrade-report.md`。报告中的目录、命令、数据规模、模型、用量与结果必须来自实际运行。初始报告未运行项写“未验证”，不要先填通过。详细合成日志与性能数据可留在`.cache/`，报告保留足以复核的摘要、样本规模和文件指针；不复制私人记录、环境变量或机器身份。

更新 `docs/README.md`、`START-HERE.md`、`docs/CONTENT.md`、`docs/AI-READING.md`、必要的OPERATIONS/ARCHITECTURE及`PROJECT-STATE.md`。新增流程链接到01/02，不重复维护互相矛盾的内容规范。解释迁移、备份、材料导入、索引重建与失败恢复的真实命令。

不执行Git提交、push、发布或部署，除非当前会话另有明确授权。现有AGENTS要求的边界继续有效。
