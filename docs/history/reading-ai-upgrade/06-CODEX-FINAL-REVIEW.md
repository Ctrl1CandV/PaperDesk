# 交给独立 Codex 会话的最终验收任务

以下内容可直接交给新的验收会话。验收者应独立读取代码与证据；不以实施者的总结或模型自评分为结论。

## 任务

你是 PaperDesk 本轮独立验收者。请先读 AGENTS.md、PROJECT-STATE.md、docs/paperdesk-upgrade/00-START-HERE.md 和 01–05，再检查实际变更、现有实施报告与测试产物。进行只读代码/内容审阅，可用项目内临时合成数据复现风险，不修改产品源码或真实用户数据。

本轮不包含任何 `grad-companion-plugin` 修改、安装或集成。当前前端与完整段落表达是保留目标；不要把重做UI或新增云平台当成通过条件。

## 按以下顺序核验

1. **完成了什么。** 将03/04要求逐项映射到实际代码与证据。明确区分已有功能、这轮新增、未实现和仅写在文档中的计划；检查三篇真实样板是否存在。
2. **数据会不会丢或被混用。** 检查旧数据库和备份迁移、导入冲突、失败回滚、流式中断、fallback、索引代次切换。确认旧导读字节/ID/章节引用、笔记与阅读状态保留，旧会话实际证据快照可回放。
3. **原文定位是否真实。** 实际打开样板的HTML章节、表格/公式定位和PDF物理页；核图像审阅记录与图表条件。确认图注-only未冒充像素核验、网页摘录未冒充全文、教学图未冒充原图。
4. **增长后是否仍可用。** 检查常规保存路径无全库snapshot，容量计数事务一致，备份独立，查询分页，正文按需加载，索引增量更新。复核05规定的规模、p95与回归结果；未运行的数据规模不能用代码推断为通过。
5. **回答是否有学术依据。** 独立抽核30题的原文答案、检索结果和最终回答；逐项区分召回、正确性、引用支持与引用覆盖。正确数字但遗漏关键比较条件也可能是不正确结论。
6. **研究建议是否有用。** 检查证据与假设分开、近邻研究和范围诚实、实验可执行、有baseline/metric/控制变量与反证。不能以文风自信、建议数量多或看起来新颖代替质量。
7. **用户体验与运行边界。** 检查来源返回、切换文章、旧版本、错误状态、取消、长回答和无材料情形，保护当前阅读宽度和段落表达；AI后端不可用时基本阅读仍可用。

## 证据要求与判定

按05的门槛报告，不自行降低阈值或把mock结果写成真实模型结果。缺真实API条件时，工程部分可单独通过，但真实问答质量必须写“未验证”，整体状态不能写成“全部完成”。如果需要调整性能目标，列出测量环境、瓶颈和调整理由，先报告原目标未达成；不改数字制造通过。

以下任一情况属于阻断项：旧数据/旧引用损坏；版本混用；不可恢复迁移；保存成功提示与实际持久化不一致；伪造原文/数字/图表；来源不支持关键结论却报告已验证；大库仍受旧16MiB导出预算阻止正常使用；明确资料不足却编造结果或创新性；未授权发送个人记录、泄露配置或擅自打开联网。

正文、来源和图表有实质缺口但如实标明时，评估它是否妨碍已承诺任务，不要求把所有论文扩展成全覆盖。可选的语义检索/重排不是按名字验收；以真实漏检和质量结果判断是否足够。

## 输出格式

首先给出分项结论：工程、内容与定位、性能、解释问答、研究探索各为“通过 / 未通过 / 未验证”。再列出阻断问题和次要问题；每项包含优先级、文件/函数、复现步骤或具体来源、实际影响和最小修复建议。

最后给出已执行命令、审阅样本和仍未覆盖的范围。使用 `templates/acceptance-report.template.md` 的结构，另存 `docs/evidence/reading-ai-upgrade-independent-review.md`；该报告是新的验收产物，不能回写实施者报告以抹平差异。

若发现问题，将具体修复清单交给实施会话，再验收相关风险；不通过删测试、删失败样例、调低题目难度或改写历史内容来使结果变绿。
