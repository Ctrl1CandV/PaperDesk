# PaperDesk：AI 阅读与研究探索的数据实施方案

版本：1.0 · 2026-10-27。性质：待实施方案，不是已交付功能或性能证明。

## 1. 目标与范围

本轮只改进 PaperDesk。保留用户已经认可的书架、导读卡、深读布局和完整段落表达。`grad-companion-plugin` 继续独立承担文献查找、阅读和科研辅助，本方案不要求修改、安装或对接它。

目标有三项：第一，让长期积累的内容、笔记和 AI 会话保存与读取更顺畅；第二，让具体问题能取回足够的原文证据；第三，让研究探索得到有依据、能验证的建议。内容生产遵循 [01](../../content/workflows/CONTENT-WORKFLOW.md)，原文定位与图表遵循 [02](../../content/workflows/SOURCES-AND-VISUALS.md)，验收遵循 [05](05-ACCEPTANCE.md)。

本轮不扩展为云平台，不增加网站账号、多人同步、无人值守搜文献或自动发布内容。现有读者主动触发的联网搜索与模型连接继续保留。

## 2. 已核实的基线与必须保留的能力

基准提交：`1668527a9e84cacac85019c569f44719bb90252d`。实施时先核对工作区，不能为复现该基线覆盖用户后续改动。

| 部分 | 已存在的能力 | 本轮重点 |
|---|---|---|
| 审核内容 | Markdown/JSON、v1/v2 schema、稳定章节 ID、不可变修订、正文哈希、受控导入与回滚 | 延续契约，按需加载；把原文证据与审核记录连接起来 |
| 个人积累 | IndexedDB、事务、修订冲突检测、独立阅读状态、备份 | 去除高频保存时的全库读取；保留原有数据身份和恢复语义 |
| AI 会话 | SQLite/WAL、请求幂等、并发上限、取消/超时、流式检查点、来源快照、版本绑定 | 增量记账、分页和可扩展备份；新增原文来源类型及兼容迁移 |
| 检索 | 已有跨导读 `search_library` 和 `read_section` | 从全库词项扫描升级为可维护索引；增加原文证据读取 |

基线的具体问题：`server/store.mjs` 每次 begin/save 构造全库快照，正常使用受 16 MiB 导出预算约束；`src/records/store.ts` 的续读/笔记更新也会创建全量个人记录快照；`src/content/repository.ts` eager 导入全部 JSON/Markdown；`server/content.mjs` 启动解析保留修订、搜索时扫描当前章节，只能检索压缩导读。这些是实现问题，不能归咎于 SQLite、Markdown 或 JSON 本身。永久链接见 [07](07-SOURCES.md)。

还须盘点关联上限：个人备份 5 MiB、AI 会话/轮数上限、内容单文件/总包预算、目录当前文章数与保留修订数。保留单次输入与内存保护，但把“导入包大小”“正常资料库容量”“导出分卷大小”分别建模，避免解掉一个限制后立刻撞上另一个。

## 3. 目标数据结构：保留现有真源，增加证据和索引

审核通过的 `content/` 继续是公开导读内容的权威来源。个人记录与 AI 对话继续使用现有存储。新增原文材料和派生索引，不把原文全文塞进每篇导读的 JSON 或前端首屏资源。

建议目录如下；Codex 可按现有模块职责调整命名，并记录实际位置：

| 位置 | 保存什么 | 生命周期 |
|---|---|---|
| `content/` 与 `schemas/` | 已审正文、元数据、目录、获准发布的教学图 | 不可变修订，既有版本继续可读 |
| `docs/research/` | 人可读的事实审查和范围记录 | 随内容修订关联，不能当成运行时全文库 |
| `private/reading/materials/` | 用户明确导入或取得的固定版本 PDF/HTML/必要图像 | 原始材料；缺失不能假装可由索引恢复 |
| `private/reading/manifests/` | 版本化材料身份清单、证据关系、核验记录、手工纠错及解析产物清单 | 权威伴随记录；纳入备份，重建索引不得删除 |
| `private/reading/derived/` | 带解析版本的段落、图表文本及定位映射 | 从原材料可重建；保留被历史引用依赖的解析版本 |
| `private/reading/index.sqlite` | 文档/来源/章节目录、检索索引、处理任务与代次 | 派生查询层；不得成为唯一原文副本 |
| `private/ai/paperdesk.sqlite` | 原有会话、回答、引用快照、检索记录 | 迁移保留既有身份；与浏览器个人记录仍明确分开 |

`private/` 已被 Git 忽略。原文材料不进入 Vite 静态资源或默认 Git 提交；允许版本控制的只应是明确审核的公开内容、小型结构化审查数据和合成测试夹具。备份界面要分别说明审核内容、原材料、个人记录和 AI 对话的范围；“索引可重建”不能被误解为“所有材料都可重建”。

身份层保持分离：`paperId` 指学术作品；`sourceRevisionId` 指固定来源版本；`materialSha256` 标识取得的准确文件字节；`parserRevision` 指固定材料上的不可变解析产物修订，记录解析器、配置指纹及输出摘要；`sourceUnitId` 指该产物中的可定位单元；`guideId/revision/unitId` 指讲解内容；`evidenceId` 连接重要主张、条件及来源单元。相同材料/配置/输出可幂等复用，输出变化新增修订。原文件哈希相同不等于学术身份相同，解析成功也不等于事实核验通过。详见 [02](../../content/workflows/SOURCES-AND-VISUALS.md)。

现有严格 v2 schema 不接受未知字段。新增材料/证据使用独立版本化伴随 schema，或设计明确的新导读 schema 版本；不得静默放宽 `additionalProperties`。保持旧 v1/v2 可读。新增 `original` 来源、检索记录或新工具时，同步修改请求/工具/快照验证、备份版本和前端引用渲染。

## 4. D1：先解决高频读写与备份耦合

### 4.1 AI 会话

在 SQLite 事务内维护每条记录的序列化字节数和总量计数。一次保存只计算当前记录旧值、新值的差额，同时提交数据和计数。新增、删除、导入、取消、fallback 替换均需覆盖；启动恢复仅定位 running 记录。全库统计只用于一次性迁移、显式完整性检查或备份，不出现在正常流式检查点路径。

把需要筛选排序的字段建成可索引列，例如 `guide_id/revision/updated_at`、`conversation_id/created_at`、`status`。原有完整 JSON 可保留作为兼容数据，但会话列表不能全表解码后筛选。使用稳定游标分页，历史消息按需读取；传给模型的历史仍受独立预算限制。

保留每轮大小、请求大小、工具轮次和并发上限等保护。正常存储不再用“整个库能否装进单个 16 MiB JSON”决定是否接收问题。改用明确的可配置运行容量与磁盘余量策略，建议起始运行预算至少容纳 256 MiB 验收集；容量接近上限时提示导出/整理，禁止自动删除旧记录。不得通过关闭全部验证来支持大库。

新备份采用分块或流式生成，记录清单、文件顺序、校验和及记录数量；恢复先在临时库验证完整性和引用，再事务导入/切换。新应用仍可读取旧 AI 备份 v1/v2；新增来源类型需要新备份版本，旧应用不支持新格式必须明确提示。运行中 SQLite 备份使用一致性快照/受支持的备份方式，不能直接复制活动数据库的单个文件而遗漏 WAL。

来源快照仍须保留历史回答实际使用的文本。允许按不可变内容哈希去重快照并用引用关联；不能只存当前 URL，日后重新抓取来冒充当时证据。首次去重属于可选优化，先消除全库保存开销。

### 4.2 浏览器个人记录

同样检查 `validateCapacity()` 的全库快照路径。续读位置和阅读状态保存只验证变更记录、相关引用与增量计数；笔记/探索保留 expected revision 冲突检测和读回确认。给常用 guide/revision/updatedAt 查询增加 IndexedDB 索引，列表分页。个人备份的旧 5 MiB 限制应与运行容量解耦，完整导入仍严格验证。本轮需实现相应IndexedDB布局迁移和新版个人备份，继续导入旧v1；以超过5 MiB的合成个人库验证保存、冲突、备份与恢复，不能只改AI库。

不要为了统一技术栈把所有个人记录迁入后端，也不要新增默认发送个人笔记给模型的行为。不同浏览器 origin 的原有边界和两类备份范围继续清楚说明。

### 4.3 迁移与失败恢复

数据库版本号、备份格式版本和导读内容 revision 是三种独立版本。先用合成旧库覆盖旧来源、fallback、损坏数据、并发和断电式中断，再实施可恢复迁移。迁移建立一致性备份，验证数量、内容摘要与关联后才能切换；失败保留旧库，不能留下半升级状态。旧会话引用、个人笔记与阅读进度不重建身份、不静默重新定位。

## 5. D2：内容按需读取及索引维护

### 5.1 目录与正文分离

构建轻量书架清单，包含列表筛选、标题、主题、当前修订和导读卡所需字段；正文与历史修订独立加载。可用 Vite 的延迟 glob/独立内容资源实现，加载的 HTML/Markdown 必须仍走现有安全渲染与校验。不能只把 eager 改成 Promise，却在 `list()`、导航或关联解析时立即 `Promise.all` 拉取全库。

`ContentRepository` 改成异步后，书架、Reader、搜索、笔记回跳和旧修订路由需一起适配。处理取消、加载失败、并发选择以及迟到响应，避免 A 文章的结果覆盖刚打开的 B。已下载内容可做有界缓存；导读正文可读不应依赖 AI 服务在线。

后端启动只装载必要目录与索引，不重新解析全部历史正文。按固定 ID/revision 读取正文，使用有界 LRU 等简单缓存。保留旧路由的明确缺失提示，不静默跳到最新版。

### 5.2 增量索引与一致性

索引更新以材料哈希、guide revision/body hash、解析配置和索引版本为键，幂等处理新增/变化项。处理状态至少区分待处理、处理中、部分可用、可用和失败；能取消、重试和恢复，失败的来源不能报告“全文已索引”。

先构建新索引代次并验证，再原子切换活动指针。每轮问答固定目录摘要、索引代次和相关解析修订；该轮所有搜索、补读和定位工具使用同一上下文，即使后台此时切换了活动代次。记录索引处理到的目录版本，旧索引与新内容不匹配时明确降级或按旧版回答，不能混用证据。删除/失效只影响后续检索，已经存入回答的来源快照和旧修订依赖保持可读。

现有导入器负责审核内容的不可变发布；在其成功提交之后登记待索引事件，或通过受控命令触发索引刷新。刷新可直接使用新增/变化清单，避免持续轮询全目录。须处理“目录已切换、事件尚未登记”时崩溃的窗口：启动或受控刷新比较当前catalog摘要与已登记/已索引摘要，根据不可变修订清单补齐遗漏任务，无需重新读取所有正文。正常成功导入后自动刷新，不需要用户手工重启才识别一篇新增内容。

## 6. D3：原文材料与检索能力

### 6.1 最小可用范围

至少完成固定版本 HTML 和有文本层 PDF 的明确导入、保存、解析与定位。扫描 PDF、复杂公式或表格解析失败时，保留原文件及页码入口，标记缺口，允许把人工核对的重要片段作为受审证据；不把 OCR/表格解析失败伪装成完整来源。具体解析依赖由 Codex 查验当前支持情况后选择，并记录版本与替换代价，不强制购买外部解析服务。

普通提问不能自动下载全书库。可由读者明确导入文件/已确认来源，或触发当前论文的材料获取。模型只可按已注册来源 ID 读取材料，不能凭一个模型生成的 URL 下载任意内容。合法材料取得和处理详情见 [02](../../content/workflows/SOURCES-AND-VISUALS.md)。

### 6.2 检索起点

先实现持久化的词项全文检索和元数据过滤，SQLite FTS5 可作为优先候选。必须用中英混合论文问题实测分词：中文短词、缩写、连字符、公式名和模型名不能仅依赖默认分词器；必要时明确预分词/词项归一化与别名表。查询字符串不直接当成检索语法执行。

段落分块保留标题路径、论文身份、实验条件及父章节关联。完整表格、公式说明和图注尽量保持语义完整；长单元可分子块，同时提供父段落扩展。导读、原文和网页摘录分别标记，避免相同事实的重复摘要挤占所有候选。

单篇问题先限定论文及版本，跨篇问题扩展候选论文；比较时保留各论文任务、数据、模型、预算、指标和时间条件。先召回一个受预算约束的候选集合，再去重、排序并按需要补读相邻段落/父章节。不能把固定 top-5 作为所有问题的唯一证据上限。

语义检索、重排和一次受限查询改写根据 [05](05-ACCEPTANCE.md) 的真实失败样例加入。若词项方案在术语变化、跨语言或探索问题上无法达到质量门槛，须在本轮完成必要的改进并比较成本；不能仅写为“将来可加”。如使用 embedding，固定模型、维度、配置与缓存键，正文变化时更新；更换 embedding 版本需要重建对应索引，不混用向量空间。

### 6.3 新工具与来源契约

保留现有工具语义；可新增 `search_sources`、`read_source_unit`、`resolve_source_locator` 等职责清楚的工具，名称可调整。参数仅使用后端登记的 ID、版本和受限查询；返回节选、定位、来源等级、实际读取范围和不足说明。

新增 `original` 来源须同时改两种 provider 的工具定义与运行路径、`server/validation.mjs`的来源/context/toolEvents白名单、`src/assistant/api.ts`类型、AI 备份验证、前端引用卡和历史回放。不要把原文伪装成 `web` 来绕过验证。旧 `L/W` 编号与旧来源仍可回放；新的编号属于本轮，不继承旧回答编号的含义。

## 7. D4：解释与研究探索的回答流程

### 7.1 阅读理解

先识别用户卡点：术语、符号、机制、推导、实验还是反例。优先利用当前导读与选文；涉及具体结果、证明假设、图表细节或导读未覆盖内容时，检索对应原文单元。用连贯语言补足必要前提，解释关键步骤如何衔接；教学例子注明是帮助理解的构造。

结论附近给出支持它的来源及定位。能只解释现有材料时不强行扩大检索；证据缺失时说明当前能回答到哪里，并指出具体待补材料。不能用模型常识补造实验数字、公式步骤、图中结构或论文结论。

### 7.2 研究探索

回答应围绕用户提出的问题或目标组织，而非自动推断其研究画像。先界定可研究的问题及约束，再给出已有证据、适用条件、分歧和可比较的相关工作。在此基础上提出一到两个值得检验的假设；每个建议说明为何可能成立、最小实验怎么做、比较基线/控制变量、评价指标、成本量级和什么结果会推翻它。

把“文献已支持的结论”“根据这些材料的分析”“待验证假设”写清楚。创新性/研究空白只能在检索范围与截止时间内谨慎讨论；本地库没有命中不能证明领域无人研究。联网关闭时，不暗示已做当前领域的全面检索。已有研究发生冲突时先检查任务、版本与预算差异，不把数字直接排大小。

建议可由用户显式保存为现有 exploration 的证据/解释/下一步，保存前预览。AI 不自动改动笔记、研究结论、阅读状态或“已掌握”。用户未选择的个人记录不会因探索模式而自动进入提示。

### 7.3 上下文、预算与可观测性

以模型实际能力或明确的保守配置建立 token 预算，分别给系统、历史、证据、工具返回和输出预留空间；未知 tokenizer 时采用保守估计并记录方法。继续保留字符/字节保护，但不能只看字符数就保证所有模型都装得下。

复杂问题允许受限的多轮取证与补读；保留总超时、取消、并发、工具次数与输出预算。API 推理 POST 不因网络异常无条件重放；幂等与已发生付费请求的处理沿用现有机制。

记录可审查的检索信息：问题范围、查询、候选/最终来源 ID、来源修订、索引代次、读取范围、预算、耗时、实际模型及已知用量。未知费用记未知，不能填零。不要保存或展示模型隐藏思维链。引用检查分两层：程序检查 ID/版本/定位存在；独立内容审阅检查来源是否真的支持论断，前者不能替代后者。

### 7.4 界面改动限于任务所需

保留现有 AI 面板及阅读宽度。来源卡区分“导读”“原文”“网页摘录”，提供直达定位和返回阅读位置；缺失时有具体说明。模式优先根据问题意图确定，如需手动选择，仅加一个简洁控件。处理进度、缺口与设置不散落到文章正文，不新建大面积技术面板。

本地材料访问沿用现有 Host/Origin/token 保护，通过验证后的材料 ID 解析；不能将 `private/` 暴露成静态目录，也不能把密钥/请求 token 放在外链参数中。引用可使用受控读取后产生的本地查看方式，失败保留原文公共入口与人工定位。原始HTML只作为原材料保存，展示使用无活动脚本的受控副本或隔离查看；清洗后的锚点/坐标需要映射核验，不能直接套用原坐标。

## 8. D5：三个真实内容样板先跑通

选择现有 `agent-memory-survey`、`streamingllm`、`rag` 验证完整链路：固定原文→必要图表核验→准确定位→关键证据映射→导读/深读→问答→旧版回放。样板同时覆盖综述、缓存机制、公式与实验对照。

对现有正文或定位元数据的修改发布新导读修订，不原位覆盖旧修订。`library-briefs.json` 单独审阅并绑定新 revision；它当前不由通用导入器接收，不要暗中改变这一边界。必要教学图只为解决具体理解困难制作，不强制每篇一图。

本轮无需把全部旧文章补成全文证据库，但三篇样板必须实做，其他文章缺材料时须准确降级。新增论文要能按 01/02 工作流进入同一链路，不依靠修改 Reader 组件或硬编码论文名称。

## 9. 完成定义

实施顺序和交付物见 [04](04-CODEX-TASKS.md)。只有存储、按需加载、来源检索、三篇样板、解释/探索回答与相应验收均有证据时，才能报告本轮整体完成。某一模型或真实材料受外部条件阻挡时，明确记录未验证项并完成其他可执行部分；测试通过、成功返回文本或演示截图都不能单独证明学术问答质量。
