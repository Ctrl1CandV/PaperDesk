# Acceptance matrix

Each item requires observed evidence. Preparation has not executed application tests; these are implementation criteria. A partial source-coverage guide can pass as a clearly labeled partial guide.

| ID | Scenario | Pass condition |
|---|---|---|
| A1 | Fresh library with no records | Honest three-guide order and purposes; no invented progress or specialist prerequisites; any guide directly accessible. |
| A2 | First article opening | Orientation precedes details/criticism; actual prose begins on first screen at 1280 and 390; complete supplied text remains available. |
| A3 | Article differences | Survey relationships, InstructGPT process/results and HELM evaluation/table remain distinct; no uniform question-card rewrite. |
| A4 | Source check and return | A representative citation per article shows exact version/locator, opens original deliberately, and returns with position/focus intact. PDF fallback label is available. |
| A5 | Diagrams/long content | Both teaching diagrams readable and identified; table/formula fixture has local overflow; no whole-page horizontal overflow at 390 or 200% zoom. |
| A6 | Coverage truth | Seed mainline/figure/appendix limitations visible without dominating prose; no complete-paper, reproduction or current-ranking claim. |
| A7 | Resume | Reload restores same guide/revision/unit and approximate position; scrolling never changes guide/original read marks. |
| A8 | Explicit states | Guide-read and original-read can differ; original version stored honestly; no action creates a mastery score. |
| A9 | Note persistence/failure | Save/reload preserves exact user text; quota/permission failure keeps draft and offers recovery; two-tab conflict preserves both. |
| A10 | Backup round-trip | Export synthetic notes and explorations including evidence/next actions, import into a fresh isolated origin, verify all fields; duplicates are idempotent; conflict preview/cancel works; invalid/new schema changes nothing. |
| A11 | Content revision | Revised text does not overwrite notes, exploration evidence or read marks; old revision is retained or old quote/orphan fallback shown; no silent false relocation. |
| A12 | Harness packet | Preview equals copied text including known version and relevant gap; unchecked notes excluded; no account/path/history metadata; denied clipboard has manual fallback. |
| A13 | Local import | Fourth test package uses the same contract without UI code change; invalid hash, missing heading/link, traversal, symlink and unknown field fail without altering current catalog. Same-key metadata or asset changes conflict even with unchanged Markdown. A new revision coexists with the old route; the current pointer controls library and editorial links. |
| A14 | Untrusted content | Raw HTML, script URLs, executable diagram directives, external images and oversized inputs do not execute or leak data; safe prose still renders. |
| A15 | Local privacy | No analytics, remote fonts/model keys or unsolicited network requests; only deliberate source opening contacts external source. Test data and screenshots contain no personal profile. |
| A16 | Accessibility and empty/error | Keyboard reaches controls/citations, dialog focus returns, headings/labels meaningful; empty search, missing content and storage unavailable have working recovery. |
| A17 | Rebuild | Locked dependency install, content validation, tests and production build succeed from a clean neutral directory. Record exact versions and actual command results. |
| A18 | Reader acceptance | Representative-page feedback addressed before broad implementation; final survey–paper–exploration loop reviewed by reader. W1 alone is not v1; tests cannot substitute for approval. |
| A19 | Guided exploration start | Explore is an actual entry with supplied editorial lenses, reasons/order, pinned reading targets and next steps; the first visit is useful with zero personal records. No prompt becomes a personal record without a save. |
| A20 | Question/evidence/action loop | From a guide selection, create an exploration; attach a second section; distinguish guide quote/original quote/reader interpretation; set a next action, follow its target and return, edit/defer and reload with data intact. Also save an independent original excerpt with its source/locator and an unlinked reader observation without fabricating a guide target. |
| A21 | Exploration resilience | Two-tab conflict, save failure, backup/restore, deleted linked note and unavailable guide preserve question/quote/provenance/next action. Cancel changes nothing; content updates do not rewrite personal thinking. |
| A22 | Honest exploration boundaries | Background reading is not proof of novelty; missing evidence is visible; no inferred interest, automatic research result or preloaded private idea. Exploration packets include only expressly chosen personal text. |
| A23 | Sustainable updates | Working importer dry-run/apply/recovery and OPERATIONS instructions add/revise a synthetic guide and editorial lens without UI edits; same-revision changed seed and duplicate lens IDs/ranks fail; invalid/interrupted import preserves the active guide/seed collection. Old seedRef resolves through the retained revision map; old reading/evidence targets remain usable or honestly unavailable. |
| A24 | Independent continuation | PROJECT-STATE states actual completed work, open issues and next package; a new developer can continue from this directory without old chat, parent/global configuration or personal data. |

Evidence table in docs/history/DELIVERY.md should record each ID as pass/fail/not-run with a concise artifact or result. Include source text changes separately from UI changes. Simulated narrow-screen testing is not a phone test. No cloud/PWA/offline/sync success is implied by these cases.
