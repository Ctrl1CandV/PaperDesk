# AI 可用性与阅读布局检查 · 2026-11-06

产品规格仍为 1.1。范围是已有阅读助手的答疑、选文、方向与工作稿，以及关闭 AI 后的阅读布局；没有内容生产、发布、Git 提交或部署。

## 已修复的实际问题

1. **选文被本地误拒。** 浏览器原来直接取 DOM `textContent`，包含表格滚动提示、KaTeX 重复表示，跨段落边界也与后端不同。用公开 LLM 综述架构章复现原 400。现在前后端共用阅读文本规则，公式与压缩引用按完整源码单元处理；仍验证固定修订、正文摘要及选文所属章节。错误提供 `selection_mismatch`，界面可明确取消附带选文并保留问题。
2. **订阅明明返回正文，却被判无答案。** 真实响应先有 completed `output_item.done`，最后 `response.completed.output=[]`。适配器仅在终态明确 completed 且最终数组为空时恢复已校验的完成项；非空最终数组仍权威，未完成项、delta 与 reasoning 不能冒充最终答案。不重放推理，不触发额度备用 API。
3. **真实内容与命令的预算不足。** 原首问固定额外扣除 10,000 字节；研究说明、目录与工具声明又重复占用空间。现在按实际序列化和有限历史分配正文，完整保留覆盖说明、固定身份、研究快照及已选材料；公开书目、引用和可选历史明确投影。必要选文优先对应真实 Markdown 区间，其来源快照可回查，不再只有章节开头。
4. **补读工具难以实际使用。** `read_section` 现在接受 `offset` / `maxChars`，按预算返回 `range`、`nextOffset` 和 `excerptOnly`。已发送身份用 `sourceRef` / `coverageRef` 引用；持久来源仍保留完整身份和实际读取区间。多次补读只合并相邻或重叠区间，不填未读空隙，不能容纳的结果不增加证据。
5. **补读后容不下方向参数。** 待提交方向预留 6000 字节，工作稿按当前正文预留，写入草稿后释放；初始导读也采用相应软预留。两个适配器继续在执行工具前检查实际 payload。真实规模的约 6 KB 创建参数已纳入回归；复杂更新确实超限时明确拒绝，保留来源和草稿，不强行通过。
6. **选文文件写到输出上限。** 默认 3000 输出预算下，两类文件曾只完成前半部分。命令现在先分配全部九节的篇幅，生成最小完整稿，默认目标不超过 960 字；仍保留出处、条件、缺口和授权边界。不自动续写，不保存中断文件。
7. **连接与未知结果恢复。** 本地令牌更新只在明确前置 `connection_stale` 拒绝后刷新一次，保持同一请求身份。其他网络、认证、额度及提供方错误不自动重放。状态、历史与设置读取有有限等待；终态事件收到后不再等待连接关闭。未确认请求的精确输入/编号保存在内存草稿，关闭再打开面板仍幂等；不承诺浏览器刷新后的草稿恢复。
8. **研究保存的边界错误。** 新建方向和积累使用同轮稳定身份；积累容器与文件一次事务保存，失败不留空记录。历史指令按原方向归属，不随后来界面关联重新分配；普通回答中的标题示例不再误识别为选文文件。并发、删除、过期版本、失败后重试和不完整回答均有合成回归。
9. **阅读与返回位置。** 关闭桌面 AI 后实际正文由 52rem 上限扩展到 68rem，重新打开恢复原列；1100–1199px 恢复目录/工具侧栏。修复关闭书架导学后的条目可见性，以及探索同步组件重复执行路由滚动恢复的问题。旧内容定位测试明确使用当前元数据或保留修订，没有改写导读内容。

## 真实模型检查

使用本应用已配置 API 与已连接 ChatGPT，保留原模型/Thinking/配置，仅在内存关闭额度 fallback 以识别实际提供方。使用公开导读、独立合成方向/工作稿、临时 HTTP 服务与内存 SQLite；没有读取真实会话、笔记、探索或原文库。应用自身必要的授权续期可由既有协议完成。没有读取其他程序凭据、改持久提供方选择或自动重试失败推理。

分批检查两种提供方的长选文首问、连续分页、方向创建、关联方向更新、积累/推进选文与工作稿整理，共 14 个不同场景。原预算、空完成和输出长度失败均保留；修复后有针对性复验，不声称所有请求都曾成功。

修复后两种提供方的全部七类功能均有真实成功记录：长选文答疑、连续分页、创建方向、关联方向更新、积累选文、推进选文和工作稿整理，合计 14 类组合，来自分批定向检查，并非同批全部请求无失败。订阅关联更新曾有一次上游连接失败、未收到 SSE、未执行工具；后来使用新的合成问题、主题和请求编号独立检查成功，提案只修改请求的 unknowns，基础修订、摘要、主题和来源轮次一致。没有自动重放原推理。

最后目录边界补充后，两种提供方的推进文件再次完成首行标题和全部九节，均明确原文本地可用性未确认。诊断汇总分别是 `.cache/reliability/live-summary-commands-repaired.json`（7 成功、1 连接失败）、`live-summary-linked-independent.json`（新独立更新成功）和 `live-summary-catalog-boundary.json`（两份文件成功）。旧预算、空完成和长度失败保留在此前批次，不计入修复后的通过数。

有限内容抽查确认：MQA/GQA 的共享维度、MoE 机制与其引用文本相符；FlashAttention 与稀疏注意力没有混同，分页未读尾段明确保留。工作稿保留原合成动机、链接和未知项，不添加实验结果。选文候选未核实的部分保留待核查性质。公开书目/导读不能证明本地原文已导入；目录提示另明确这一边界。生成内容仅作有限抽查，不能当作全面学术质量验收：一份最终 API 推进文件仍把导读中的自编缓存形状例误称“表1”，图表/数字的原文归属仍需事实审阅。

完全合成的真实问答与安全事件形状留在忽略的 `.cache/reliability/`，报告不复制正文、配置或凭据。仅保留事件类型/完成状态/可见字符数等诊断；隐藏 reasoning 与 opaque 内容不落盘。

## 继续使用与边界

重新构建后重启平台，正常入口仍是 `npm start`。没有改动已审核正文、已有阅读/研究记录或默认模型配置，没有 Git 提交、推送或部署。

新增 guide `readRanges` 的数据需使用本轮源码读取；新程序仍读正常旧备份，不保证旧程序能读新范围。回退另存升级前备份，不剥字段降级。很大的选中材料或模型参数仍可能超过保守预算，此时拒绝发送/写入并保留现有内容。真实 Tavily 搜索、长期网络可靠性、其他浏览器引擎和真机未在本轮验证。
