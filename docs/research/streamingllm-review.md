# StreamingLLM 来源核查与作者自审

核查日期：2026-10-24。本文为新增研究论文导读的作者核查记录，独立内容审阅和平台视觉审阅由整合流程另行完成。

## 选文理由

《Efficient Streaming Language Models with Attention Sinks》把持续输入问题中的计算状态管理单独解释清楚。它可承接 Agent 记忆综述，并帮助区分累计处理长度、近期可用上下文和长期证据恢复。当前选择优先解释一个可核验的基础机制，不宣称这是最新方案或可直接用于实时 Agent 的完整架构。相比立即加入更完整的流式 Agent 系统，本文更便于学习问题界定、受控干预和性能证据的边界。

## 核心主张与边界

1. 四百万 token：依据 §4.1 / 图5 的 PG19 拼接语言建模，保留 Llama-2 2048、其他三家族1024的缓存设置；不称为四百万上下文或长期自由生成一致性保证。
2. Attention sink：解释为作者提出并用换行符替换和预训练实验支持的注意力分配机制；不称为历史摘要，不由softmax直接推出四token普适定律。
3. 双段缓存：明确 $x+y$ 是初始加近期的总预算，以及 RoPE Key 在旋转前缓存、连续缓存位置与 ALiBi 偏置的处理。
4. 22.2倍：指定单A6000、Transformers、Llama-2-7B/13B、相对每步重算窗口的每token收益；图10最大例来自13B/4096的约2355/106毫秒，不推广为任意部署的固定提升。
5. 记忆边界：附录 C 的越界失败和附录 D 的语义开头丢失明确呈现；未断言全部旧信息在当前表示中毫无间接影响，而是不把固定缓存视作可恢复全部历史的记忆。
6. 专用sink：160M模型的从头训练实验，与既有模型无需微调的主方法分开；不声称在提示词前临时加词即可复现。
7. 学习衔接：计算状态、长期记忆、在线决策的分工是编辑解释；没有把本文写成解决中断推理或异步观察的证据。
