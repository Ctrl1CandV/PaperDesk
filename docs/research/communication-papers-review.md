## 主张检查与边界

- **AutoGen**：实际查看 PDF 第3、4页，重点图2；核对原文方法及六类应用。将计算与控制流区分，明确自然语言与代码共同组织对话。ALFWorld 的 ReAct 跨系统基线与 AutoGen 底座模型不同；数学应用各基线覆盖范围不一；群聊例子规模有限。因此不沿用“多 Agent 普遍优于单 Agent”的结论，也不将2023年论文写成当前SDK教程。
- **CAMEL**：实际查看 PDF 第3、4、5、8、9页，重点图1、公式1–4、停止条件和表1。AI user/assistant 是交互角色；任务具体化可能增加假设。76.3% 是 AI Society 人工比较回应的偏好比例，评价收集453份回应，不能当作任务执行成功率。100项AI Society、100项Code、GPT-4汇总过程与单次GPT-3.5基线分开说明；人评仅覆盖AI Society。§5.3是生成数据微调后的单模型结果，不能冒充运行时协作结果。
- **AgentPrune**：实际查看 PDF 第3、4、8、9页，重点图3、图5、表3。空间DAG是该执行抽象的条件；学习掩码之后一次剪枝并固定结构；不是模型参数剪枝或每条消息都在线判断。§3.4限制复杂度和Agent数量，成本须包含学习阶段。表3 AutoGen/HumanEval原始输入、输出token数已逐格核对。
- **AgentPrune v1 数值疑点**：表3 GSM8K 的部分括号百分比与所列原数不一致；表1部分平均值需回到分项检查。导读不复制其统一节省范围、不重算这些行来补成作者结论；公式13未作为已验证成本保证使用。保留这些版本疑点，不用后续会议版数据悄悄替换。
- 三篇的教学情境、流程图和后续研究建议均标为教学或编辑推导，没有虚构为原文实验；原文图未直接重发。论文公开作者署名保存在 metadata 中。
