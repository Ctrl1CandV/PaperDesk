# 模板使用说明

本目录帮助实施者把要求落到可检查的记录，不预先替代运行时 schema、实际证据或质量结果。

- `evidence-record.example.json`：纯合成关系示例，示意导读修订、原材料、解析单元、定位及分开的核验状态。所有 ID、页码和主张均不能用作真实内容。实现先定义独立伴随 schema，再迁移成受校验记录。
- `qa-case.example.json`：两个未执行的题目种子。第一题数值根据[StreamingLLM v4 附录 C 表 7](https://arxiv.org/html/2309.17453v4)核对；原材料指纹、本地来源单元和独立验收金标准仍待建立。第二题示范研究探索的评价维度，不设唯一“正确研究方向”。
- [原升级验收报告模板](../../history/reading-ai-upgrade/templates/acceptance-report.template.md)：保留在历史任务中，可按具体维护需要参考。未运行项保留“未验证”，不要把模板当作已通过证明。

`null` 表示当前未取得或不适用的值，不是空值通行证；正式 schema 应按状态定义必填字段。不得编造哈希、锚点、边界框、图像核验记录或测试结果以填满字段。

题集必须区分材料模式。同一事实题在“只有导读”时可能正确地回答资料不足，在“原文已取得且可检索”时应给出有支持的精确答案。不得用模式切换掩盖原文模式的检索失败；先固定题目、可用材料及预期行为，再运行模型。

原升级的[验收建议](../../history/reading-ai-upgrade/05-ACCEPTANCE.md)曾提出30题、必要证据、独立金标准和可重复测试命令；当前维护以个人使用基线为准，需要质量评估时可参考该方法。本包仅给出样式与种子，**没有附带一套已跑通的30题数据或通过证明**。金标准应供评审使用，不能塞入被测模型的检索语料。
