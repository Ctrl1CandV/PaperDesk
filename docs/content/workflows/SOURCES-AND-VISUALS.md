# 原文材料、图表核验与证据定位

## 目标与现有基础

本文是 PaperDesk 持续制作内容时使用的原文、定位与图示规范。现有导读、深读页面、schema-v1/v2 内容包和已实现的原文材料库继续按当前契约维护，让读者及 AI 能从一个具体结论回到其实际依据。最初的工程任务与验收范围见[历史材料](../../history/reading-ai-upgrade/README.md)。

项目保存来源 URL、版本、citation inventory、阅读范围、图像核验声明及不可变导读修订；Transformer 的研究记录还逐项核对了主张、实验条件和原文章节，并指出会议摘要网页与 PDF 的数值不同。这些已有实践与原文材料、解析和证据映射共同构成数据链；单篇核验范围仍以具体记录为准。[S1][S2]

完成后的正常路径应支持：在导读或深读中查看关键事实，打开相应证据说明，再定位到**当时使用的原文版本及页面、段落或图表**。查询旧导读仍打开旧依据，不因当前推荐版本改变而跳转到新版。

## 一、固定材料，分别管理身份与文件

学术身份继续使用 `paperId` 及经核实的 DOI、arXiv ID 等。`materialSha256` 只标识取得的原始字节；它不能代替论文身份，也不能独自证明文件来自所声称的出版物。

建议新增独立伴随数据，至少区分以下对象。字段名是实现候选，须定义新 schema、兼容规则与迁移；现有 v2 使用严格字段约束，不可直接向其 JSON 塞入未知属性。[S1]

| 对象 | 建议记录 | 作用 |
| --- | --- | --- |
| 原文修订 | `sourceRevisionId`、`paperId`、版本说明、原始/最终 URL、取得时间、`materialSha256` | 固定实际使用的材料，区别版本更新、镜像和文件变化 |
| 解析产物修订 | `parserRevision`、材料指纹、解析器及版本、配置指纹、输出摘要、完成状态与缺口 | 固定一次不可变解析产物，说明文本和坐标如何得到 |
| 来源单元 | `sourceUnitId`、所属修订与解析批次、单元类型、章节路径、内容及定位 | 承载段落、表格、公式和图片，支持精确检索 |
| 证据关系 | `evidenceId`、导读修订/单元、关键主张、来源单元、条件、归属、核验记录 | 连接解释与依据；一条主张可需要多个来源单元 |

取得材料时校验实际文件类型、可读性及其论文身份，计算原始字节指纹，再保存材料记录。原始文件不被清洗文本覆盖；清洗、OCR、表格恢复、裁图都是派生物，保留各自生成记录。HTML 还需记录正文依赖的图片等资产；只存一个外部 URL 不等于已保存对应材料。

同一学术版本可能有 PDF、HTML 和独立图片等多个材料；各材料分别记录真实字节指纹和来源关系，不假定不同格式内容完全等同。每条证据绑定实际使用的材料与解析修订；PDF 与 HTML 的定位不能直接互换。

原文及可能包含用户材料的解析正文放在后端运行目录，不打包进前端，也不默认提交 Git。其备份应包含原始文件、材料清单和证据映射；可重建索引另行管理。材料身份映射、`evidenceId`关系、人工/AI核验和手工纠错是权威伴随记录，建议存于`private/reading/manifests/`，不能只存在于可删除索引。公共内容继续采用当前审核、导入和不可变修订机制，不让原文摄取直接改写已发布导读。[S3]

同一 URL 返回不同字节时重新核对版本和文件身份，保留旧材料；不能覆盖旧文件后继续使用旧指纹。`parserRevision`表示固定材料上的不可变解析产物修订，记录解析器、配置指纹及输出摘要；相同材料、配置与输出可幂等复用，产物改变必须新增修订。旧证据所引用的单元与定位仍须保留，或经过明确、可审计的映射迁移。若材料已不可取得，保存缺失状态，不能靠改写 URL 伪装恢复。

原始HTML字节用于溯源，浏览器展示使用无活动脚本的受控阅读副本或隔离查看器，不把任意原始HTML直接注入应用同源页面。清洗/重排后的定位需要保存并核验原文到展示副本的映射；映射未知时使用章节/页级回退，不能展示错误高亮。

## 二、解析必须保留可定位的结构

按实际结构保留标题层级、段落顺序、图表标题、公式编号及其上下文。表格单元与表头、单位、脚注一起管理；公式与符号定义、适用条件一起管理。检索可返回较小单元，展示及回答时按需要补回邻近内容，避免一个数字脱离分母或一个公式脱离假设。

| 原文类型 | 定位要求 | 缺少精确定位时 |
| --- | --- | --- |
| HTML | 保存固定版本 URL、实际存在的锚点、章节路径；打开核对锚点对应内容 | 提供版本入口、章节名与可搜索的短文本，不编造锚点 |
| PDF | `physicalPage` 从文件第一页按 1 计数；另存实际识别的 `printedPageLabel`，允许为空 | 显示“PDF 第 N 页／印刷页标签”，让读者手动定位 |
| 图表、公式 | 记录所属页面或章节、原始编号、标题及来源单元关系 | 保留真实编号和上下文，未确定位置就标待核 |
| 版面块 | 只有取得真实坐标时保存边界框，并记录坐标原点、单位、页面尺寸及旋转 | 不画假高亮；退回页面级或章节级定位 |

PDF 的 `#page=n` 只是打开指定物理页的候选方式，应在实际支持的阅读环境验证。若外部查看器忽略 fragment，清楚显示手动定位信息并允许打开完整原文。不能以“链接可访问”证明“跳转位置正确”。当前项目已经约定物理页与手动定位，本轮将它落实到后端来源单元和入口验收。[S1]

解析错误需要局部暴露：例如双栏段落交错、表头丢失、上下标错位或扫描页无文本。错误单元可暂不参与精确回答，其余已核材料仍可使用。对关键公式或表格，OCR 文本必须回看原页；模型觉得合理、公式能渲染，都不能证明与原文一致。

## 三、图表和公式的核验标准

只有打开了该固定材料对应的实际页面或图像像素，并辨认与当前解释相关的内容，才可以记录“已查看／已核对”。获得文件、提取图注、生成截图或运行 OCR 本身均不满足这一条件。`caption-only` 不得自动升级为图像已核状态。

核验记录至少包含材料指纹、页面或资产标识、查看时间、执行者及核验范围。执行者可以是具备视觉能力的 AI 或人工，但必须如实区分，不把 AI 查看改称人工审阅。历史导读已有的 `figuresViewed` 保留原声明；不能因导入材料库而追认成这轮新核验。

- **架构图：**核对模块、箭头方向、图例、共享或重复部件，以及训练和推理路径。正文解释至少连接输入、处理、输出与关键设计目的。
- **结果图与表：**核对坐标或表头、单位、分母、数据划分、baseline、预算、误差表示和脚注。开发集消融与测试集结果不可直接混成同一提升。
- **公式：**核对符号、下标、维度、假设、求和或归一化范围，解释它在本文解决什么问题。补充推导标为教学解释，推不出的步骤保留断点。

核验粒度应能表达“已看图像，但其中某项看不清”。视觉已查看、定位已核实、数字已比对、主张获得支持是不同事实，不合成一个含义不明的 `confirmed`。来源支持判断仍需把证据与实际句子对照；引用存在并不代表推断成立。现有 Transformer 审查表可作为这类核验记录的种子案例。[S2]

## 四、教学图与专题深读按解释需要增加

当前正文保留连续讲解，新增图示用于解释空间关系、信息流、比较维度或难以顺读的步骤。可维护的精确示意优先使用仓库原生 Mermaid 或 SVG；必要时扩展受控渲染与验证，不直接放开任意脚本或不受检查的 SVG。现有 Mermaid 安全边界继续有效。[S1]

教学图明确标注“教学示意，非论文原图”，并说明依据及省略内容；原图使用则保留原图身份与来源，不能用重新绘制掩盖内容改动。文字仍需解释图中关系、适用条件和读法，并提供可读的替代说明。图示不能替代关键论证，也不要求每章配图。

专题深读只为确实存在的理解缺口增加，例如注意力遮罩的实际信息通路、检索检验如何设计、消融支持哪一项机制。专题要写清问题、依赖知识、解释过程、证据及边界，并链接回原导读单元；不要把整篇论文统一加长。必要时形成新的导读修订或独立专题，保留既有深读内容和旧入口。

界面保持现有阅读布局，在重要事实、公式、图表附近提供简明原文入口；缺少精确定位时直接显示可用的位置。可借鉴 ScholarPhi 在术语或符号出现处提供相关定义及上下文入口的思路，但不据此承诺 PaperDesk 已实现同等效果，也不照搬整套交互。[S4]

## 五、AI 回答必须能沿同一证据链回查

AI 可使用审核后的导读帮助定位主题，具体事实、数值、机制和比较结论再回到可用原文单元。回答引用同时保留导读修订与原文修订：前者说明从哪里进入问题，后者说明事实依据。只有导读时，应明确依据是导读，不生成从未读取的原文引文。

`evidenceId` 连接关键主张及其必要条件，并区分作者主张、直接呈现的数据、综述转述和教学解释。证据绑定`sourceRevisionId + materialSha256 + parserRevision + sourceUnitId`，不能只保存“最新解析”。综述引述某论文不等于平台已读被引论文；跨文比较还需核对任务、指标、数据和预算是否可比。索引命中或相似度高不属于学术支持证明。

下例仅说明关系，全部 ID 均为 synthetic，指纹为占位文本；它不是现有 schema、生产记录或可直接导入的数据。正式模板由实现定义新 schema 后校验。

```json
{
  "exampleOnly": true,
  "evidenceId": "synthetic:evidence-001",
  "guide": { "guideId": "synthetic-guide", "revision": 1, "unitId": "u01" },
  "paperId": "synthetic:paper-001",
  "sourceRevisionId": "synthetic:source-r1",
  "materialSha256": "<由真实原始字节计算，示例未提供>",
  "parserRevision": "synthetic:parse-r1",
  "sourceUnitIds": ["synthetic:table-001"],
  "locator": { "physicalPage": 4, "printedPageLabel": "3", "label": "示意表 1" },
  "claim": "示意条件下，方法 A 在指标 M 上高于基线 B。",
  "conditions": ["同一测试集、指标定义与预算"],
  "attribution": "author-reported-result",
  "verification": { "visual": "not-reviewed", "support": "unreviewed" }
}
```

## 六、缺口处理与验收

| 情形 | 系统行为与核验要求 |
| --- | --- |
| 未取得原文 | 保留已有导读和来源入口，标“仅导读可用”；不得承诺全文回答 |
| 解析部分失败 | 记录失败单元及原因，阻止其冒充精确证据；修复后生成新解析批次 |
| 只有图注 | 可说明图注报告的内容，不能描述未看的图形关系或将图像标为已核 |
| 出现新版 | 新建原文修订并比较变化；旧导读继续绑定旧版，新结论重新核查 |
| URL 失效 | 有已验证本地材料则继续按原指纹打开；没有材料则明确失效，不静默换版 |
| 定位或证据冲突 | 让读者看见实际缺口，降低回答结论强度；修复前不宣称核验完成 |

最小验收覆盖一份 HTML、一份有印刷页差异的 PDF、一张复杂图、一张带脚注的结果表及一个公式。逐项从界面引用打开固定材料、核对位置与上下文；再验证旧导读、失效 URL、解析失败和图注-only 情形。重新解析后，旧引用仍可解释且不会跳到错误段落。最终报告分别写清实际取得、实际解析、实际像素查看和实际事实核验的范围，不用一个通过标记代替四者。
